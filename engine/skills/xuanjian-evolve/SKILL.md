# 自动进化

前面三轮知识摄取都是手工做的，每轮都要重新回答三个问题：还差什么没读、这一轮改出了什么、有没有把旧结论改坏。第三个问题最要命——第二轮补完打分基准后，一次撞见两处重大误判（1957 坤造由「身旺」改 110.5 中和偏上、1985 乾造由「身旺至极」改 81 偏弱），那次是运气，不是机制。

本技能把这三问变成可查、可跑、可留痕的东西。

## 一、五步循环

| 步 | 做什么 | 谁做 | 产物 |
|---|---|---|---|
| **摄取** | 查台账，取未读清单，下载并读完 | 人读，脚本排优先级 | 登记台账一行 |
| **提炼** | 把新东西写成册页或规则 | 人写 | 知识库新册／规则库新编号 |
| **回测** | 七十三题校准 + 在办档案**两道**回归 | **脚本跑** | 漂移报告 |
| **同步** | 知识库同步闸 + 双向一致闸 | **脚本跑** | 两边口径是否分岔 |
| **沉淀** | 追写档案、更索引、升版本、写日志 | 人做，脚本校验 | 版本递增、进化日志一行 |

**第四、五步是后加的**：知识库改了，专家团和排盘工具两边都会读到同一份册页，若只改一边，同一个八字在两处会说出两套话（v1.3–v1.5 就这么欠下过一整层能力——工具加了紫微五层，专家包里零处提及）。

**自动的只有第三、四步的校验与第五步的日志采集**。摄取与提炼必须人来——术数的内容判断不能交给脚本。

**学习引擎四件（v1.55.0 加，见 `TR109`）**：

```bash
python3 study_state.py 状态 / 校验 / 初始化          # 台账·基准·日志·掌握度 四件一套
python3 study_state.py 迁移 [源] [--到 目标] [--覆盖]  # 换工作区先搬进度，带备份
python3 distill.py 提炼 <原文...> --out 目录          # 抽候选断言，只提案不裁决
python3 mastery.py 出题 --book 96 --limit 8 --out 题.json
python3 mastery.py 判卷 --questions 题.json --answers 答.json
python3 mastery.py 报告 / 到期
python3 study.py 状态 / 复盘 / 下一批 / 提炼 / 出题 / 判卷
```

**基线两件（v1.56.0 加，见 `TR110`）**：

```bash
python3 baseline.py 覆盖                     # 全册出题能力盘点：可测／勉强／不测及原因
python3 baseline.py 出卷 --books 01,39,43 --per 6 --out 目录 [--nonblind 96,97]
python3 baseline.py 判卷 --paper 卷.json --key 答案.json --answers 答.json
python3 baseline.py 落册 --paper … --key … --answers …   # 写进掌握度
python3 baseline.py 基线                     # 逐册分档＋盲测/非盲分列
```

**为什么基线单独一层**：`mastery.py` 一次只能测一册，六十七册按那个速度铺不完——
进度里长期只有「已测 1 册」，平均 0.62 这种数没有统计意义，报出去反而误导。
`baseline.py` 把「出卷／作答／判卷／落册」一次铺开二十册以上，并且**卷子不带答案**
（`paper.json` 只有题面，`key.json` 锁答案），作答阶段只给卷面。

**裁决一件（v1.56.0 加，见 `TR110` §3）**：

```bash
python3 ruling.py 清单 [--verdict NEW] [--limit 20] [--offset 0]
python3 ruling.py 裁 D001 采纳 --理由 "..." [--归 96]
python3 ruling.py 裁 D002 驳回 --理由 "..."
python3 ruling.py 改判 D001 驳回 --理由 "..."      # 改口留痕，旧条标 superseded
python3 ruling.py 台账 / 草稿 --out 目录
```

`distill.py` 只提案不裁决是对的，但**提案没有消费端等于没提案**——226 条躺在
`distill.json` 里一条没裁，攒得越多越像成绩，其实一行知识都没进库。三条纪律：
不许一键全采纳、每条必须写理由、已裁不许重裁（改口走 `改判`）。

**为什么加了这一层**：台账原先只记「读没读」。六十七份读过的资料里有多少真能答出来，
没人量过；而台账、基准、日志三件各写死一个绝对路径，换个工作区就等于从头开始。
这四件把「学到哪、会不会、下次复习哪册」变成可查可跑的数。

台账本体在工作区 `命理档案/方法论/摄取台账.md`，基准与进化日志在同目录
`回归基准.json`、`进化日志.md`。

**摄取器 `ingest.py` 只取回原文，不做提炼**。它解决的是摄取那一步卡在「手工下载」上的问题——
台账能排出该读什么，但过去取正文要人点链接、另存、再打开。资料库有下载与解析接口，
这一段机器能做（网盘 `.docx` 直接剥出纯文本）。**读完怎么提炼、落到哪一册，仍然是人做的事**——
术数的内容判断不能交给脚本。

## 三、回归为什么必须两道

回归基准原先只比打分（专家团 `score.py`）。工具后来陆续加了紫微五层、天干五合、
年过六十降档、订正层、大运排向——**那些改了之后，只看打分的回归器一路绿灯**。

| 道 | 跑什么 | 比什么 |
|---|---|---|
| 第一道 | 专家团 `score.py` | 总分、天干分、地支分、档位、岁运要点 |
| 第二道 | 排盘工具 `engine-dump.ts` | 四柱、大运签名（排向＋首步）、紫微签名（命宫＋主星＋身宫＋五行局）、用神、五合、降档、格局数、神煞数、订正层 |

第二道由工具侧 `scripts/engine-dump.ts` 出快照，专家团这边调它——**两边同源，但不共用一份代码**，
所以必须各自跑、各自比。任一跑道跑不动（工具不在／生辰解析不出），明确报「未回归」，
不并入「全部通过」。

**订正层是档案定案，不是引擎结论**：它变了说明档案改了，脚本只提示「请确认为何改」，
不判漂移。`regress.py 分歧` 把引擎判语与档案定案并排摆出来——两套口径在印重／比劫重
之盘上本来就会相反，这是**已知分歧**不是问题，但分歧面必须常摆在眼前。

## 四、七条铁律

### 1. 漂移必须先分辨，再处置

引擎一改，回归器若报漂移，**不能直接改基准了事**。先判断：

- 是**订正**——新规则发现旧结论错了（如 1985 乾造那次），那就改档案卡片与分析记录，写明订正原因，再跑 `建立` 刷新基准；
- 是**回归错误**——新改动破坏了原本对的结论，那先修引擎，基准不动。

把基准改掉来消掉红色，等于把警报器拆了。

### 2. 读完必须登记，登记才算读完

读过没登记，下一轮台账还会把它排在待读里，白读一遍。登记时顺手写清「落到哪一册」——
写册号不写册名，脚本要靠册号去工具侧对覆盖表。没写册号的，`ledger.py 待编码` 会单列出来追。

### 3. 假绿灯比红灯危险

回归器报「全部通过」时，先问一句：**它到底测了什么**。只比打分的那些轮次，
紫微五层改了、五合改了、降档改了，它照样报通过——那不是没改坏，是根本没测到。

所以：新增一层引擎能力，就要往回归基准里加一个维度；跑不动的维度要报「未回归」，
不许并入通过。**宁可看见红灯，不要看见假绿灯。**

### 4. 外部情报先核验，再提炼（2026-11-04 加）

第十二轮起，凡外部 GitHub 项目／数据集／模型，**先过 `OB95` 的核验总表**（仓库是否真实、许可四段、宣传计数、自报成绩、404 路径），核实过的才进提炼；未核实项标「未核实到」，不推测功能、不写进定案级规则。这一条是前三条闸的**前置闸**：摄取器取回的原文若来自未核实来源，登记也不能算读完。**只借机制、不搬实现**——本轮新增的 `kauding.py`／`source_gate.py` 与五册均为本馆自撰，未引入任何外部代码或语料。

第十三轮起，凡涉及**模型训练或语料摄取**，再加一道 `TR100` 前置闸：先核 `DATASET-LICENSE` 的引文例外、剥离倪师原话正文、跑 `assert_no_leak()`；语料只从 GitHub Releases 取并留 SHA-256，不从 `ouranic.cn` 抓任何内容。训练产物须过 `eval_train.py` 的安全闸门，`safety=FAIL` 一律不进回归基准；回归基准新增三项：`corpus_gate.py --selftest`、`build_corpus.py --selftest`、`eval_train.py --selftest`。

### 5. 学了不会，等于没学（2026-11-05 加）

**台账的「已摄取」只表示材料处理过，不表示掌握**。报进度必须同时报已测册数与平均掌握度，
不能只报好看的那个；`mastery.py` 判出来的低分不许靠放宽阈值凑。挖空题答错就是答错——
2026-11-05 闭卷测 `38` 合婚册 5/8，两处错在把四柱「婚姻宫」写成紫微「夫妻宫」，
**语义没错、术语归错体系，照样判错**：判松了，测的就不是掌握。

配套两条硬约束：① **学习状态必须可携带**，写在专家包之外的单一状态根里，换工作区先
`study_state.py 迁移`；② **提炼可半自动、裁决不可自动**，`CONFLICT` 一条都不许自动采用，
`NEW` 未核定不许落册。

### 6. 判新≠判值不值，裁前必须重跑（2026-11-05 加）

`distill` 判 NEW 判的是**字面相似度**——库里找不找得到相近说法。找不到就是新，
这个判定没错；错在把 NEW 当成「该入库」。226 条 NEW 里大半是课堂口语碎片，
于是加 `admission` 四级（规程／案例／碎片／长段）另判值不值：实测**规程只占 46 条（20%）**。

更硬的一条：**裁决前先重跑 `distill`，对着最新库判**。第一次跑时库里有没 `KB96`／`KB97`，
179 条判 NEW；写完这两册再跑，NEW 掉到 121、KNOWN 涨到 33。我据此复核，发现已裁为
「采纳」的 9 条里有 **5 条其实逐字写在 96／97 里**，只好改判驳回。**库一变，昨天的
新知识今天就是重复**；拿旧提案的判定去裁决，等于照过期的地图找路。

### 7. 量不出来的进步，不算进步（2026-11-05 加）

报进度必须同时报三件：**已摄取／已测册数／平均掌握度**，缺一件就是报喜不报忧。
2026-11-05 的真实数是：摄取 67/172（38%），已测 22 册，盲测均值 0.6618。
**22 册里 45 册仍属「未测」——那是未测，不是已掌握。** 同理，提炼覆盖率 22.6%
不许报成完成；出不了题的册是盲区，不许从分母里悄悄消失。

## 五、优先级

同类资料读了一批之后，下一批按这个顺序取：

1. **主课笔记**（53 课笔记）——体系主干，先补完
2. **实践课与作业**——有答案，可用来做算法回归
3. **历年答疑**——真实反馈最多，用来校验断语
4. **手面相**
5. **居家办公风水**

当前进度：合计 **67 / 172（38%）**。四柱理学 62/127（48%）、手面相进阶 3/21（14%）、居家办公风水 2/24（8%）。掌握度仅测过 1 册（0.62 半熟）——**67 册里 66 册属「未测」，不是「已掌握」**。

## 六、与排盘工具的双向一致

排盘工具（`xuanjian-paipan`）有两道闸门，监视知识库五十七个文件（含本技能）：

```bash
cd <排盘工具目录>
npm run kb:check     # 单向：哪些册页变了、哪些要补功能
npm run kb:gate      # 有待办时退出码 3
npm run sync:check   # 双向：版本对齐、覆盖表模块存在性、技能登记、成员引用
npm run sync:gate    # 有不一致时退出码 3
python3 evolve.py 同步    # 两道连跑（在专家团这边跑）
```

**只跑一道是不够的**：`kb:gate` 只看「知识库改了工具有没有跟」，
`sync:gate` 才看「工具加的东西专家团知不知道」。v1.3–v1.5 给工具加了紫微五层，
专家包里零处提及——就是因为当时只有单向闸。

**册页落库后还有一步**：`ledger.py 待编码` 列出每册在工具覆盖表里的状态。
没登记的册，工具永远不会去实现；登记了 `pending` 的，等着下一轮编码。

**两边口径有冲突时的处置**（已发生过一次）：

- 工具旺衰主口径是「透藏加权占比」，专家团用课程打分法，两套在印重／比劫重之盘上会给相反结论（1985 乾造：工具说偏旺，专家团订正为八十一点〇分偏弱）。
- **不许静默顶替**。工具侧新增 `src/analysis/dingzheng.ts`——不动引擎，只把命理档案里的订正定案并排呈现，附规则编号与待验证项。
- 分歧面用 `regress.py 分歧` 常摆出来看。**分歧项变了才需要介入**，不变就是已知分歧。
- 想改主口径，须先改档案与规则库，再同步工具，两边一起动。
