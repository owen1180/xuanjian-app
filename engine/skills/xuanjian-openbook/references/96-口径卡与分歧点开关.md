# 96 · 口径卡与分歧点开关

> 思想来源：`Horosa` 的「口径卡／参数束预设／分歧点开关／跨技法口径冲突检出」、`ziwei-doushu` 的 `school-config.ts` 与 18 个回归脚本、`mingpan` 的输入契约、`yuan` 的统一输入包。**schema、字段、脚本与规则句均为本馆自撰，未复制任何实现。**

## 一、为什么需要这一册

同一副八字、同一张紫微盘，只要在**历法、晚子时、闰月、真太阳时、亮度基表、四化流派、定年界线**任一处取值不同，结论就会分岔。过去这些是隐性默认值——出了分歧只能争「谁算得准」。本册把它们变成**一等公民数据结构**：先出卡，再排盘，再互证；**卡不一致，结论不许互证**。

## 二、统一输入包（主理人唯一裁定，成员只读）

```json
{
  "name": "", "gender": "male|female",
  "birth_datetime": "YYYY-MM-DD HH:MM",
  "calendar_type": "solar|lunar|unknown",
  "birthplace": "至少到城市", "timezone": "IANA 名", "longitude": null,
  "question_focus": [],
  "unknown_time": false
}
```

- **所有成员只从这一份包派生**，任何成员不得为方便自己那门而临时改口径，也不得另向用户重复问询。
- `calendar_type=unknown`／农历未确认闰月／只知大概时辰／出生地不足城市级时，主理人**先补问再派单**；单轮追问不超过 3 个，优先级固定：时间分钟精度 → 历法与闰月 → 城市与真太阳时 → 2–3 个已发生的人生节点（用于校准分歧）。
- 输入校验：出生年 1900–2100、性别枚举、时区 IANA、`isLunar` 显式布尔。缺参或非法参返回**结构化错误对象** `{error_class, message, next_step, candidates}`，不抛 traceback、不让成员「猜一个值」补齐。
- `unknown_time=true` → 强制 `hour=0`（子时）且**不换日**，结果页必须标「时辰为假设值」。

## 三、口径卡 schema（`kauding.py new` 产出）

```json
{
  "card_version": "1.0",
  "technique": "ziwei",
  "school_preset": "tianji-default",
  "school_note": "倪海厦《天纪》三合派；四化固定，大限只看宫位移动",
  "engine_version": "xuanjian-1.51.0",
  "input": { "...": "见 §二" },
  "switches": {
    "calendar": "solar",
    "hour_index": "0-11",
    "true_solar_time": "on",
    "late_zishi": "next-day",
    "leap_month": "split",
    "dst_cn": "detect-only",
    "year_boundary": "lichun",
    "zi_chu_huan_ri": "23:00-next-day",
    "brightness_school": "quanshu",
    "sihua_school": "tongxing-feixing",
    "dayun_age": "nominal",
    "judging_basis": "score-py"
  },
  "provenance": { "source": "本馆口径卡 v1.0", "created_by": "主理人", "created_at": "" }
}
```

**卡内任一字段变化，整卡重渲染并重算盘面；禁止只替换断语文本而不重算。**

### 参数束预设（预设＝一组命名参数取值，不是文案模板）

| 预设 | 联动写入的开关 | 说明 |
|---|---|---|
| `tianji-default`（本馆默认） | `solar` / `0-11` / `next-day` / `split` / `quanshu` / `nominal` / `score-py` | 用户未指定流派时**必须自报所用默认档名**，不许静默使用 |
| `ni-school-leap` | 仅把 `leap_month` 改 `next-month`（倪师派整月归下月） | 切换后须写明「与默认档不同，结论不互证」 |
| `current-day-zishi` | 仅把 `late_zishi` 改 `current-day` | 晚子时留本日 |
| `modern-v2` | 仅把 `brightness_school` 改 `modern-v2` | 对齐 v4.0 数据集生成口径，仅供对拍，不作本馆默认 |
| `custom` | 用户自定完整参数束，可命名复用 | **禁止把自定义值回写覆盖内置预设** |

### 十项分歧点开关（逐项给候选值，可单独覆盖预设）

| # | 开关 | 候选值 | 影响 |
|---|---|---|---|
| 1 | `late_zishi` | `next-day` / `current-day` / `all-current` / `day-cur-time-next` | 晚子时换日 → 日柱时柱、命宫全盘 |
| 2 | `leap_month` | `split`（默认，前 15 天归上月／后 15 天归下月）/ `next-month` / `prev-month` / `origin-month` | 闰月归属差一个月，命宫身宫四化整盘皆错 |
| 3 | `year_boundary` | `lichun`（默认，按节气时刻）/ `jan1` / `lunar-newyear` | 年柱、生年四化 |
| 4 | `true_solar_time` | `on`（填了出生地）/ `off`（没填，**明示未校正**） | 时辰边界整体挪动 |
| 5 | `dst_cn` | `detect-only`（默认，只判定 1986–1991）/ `manual-adjust`（用户亲手点、可撤销） | **不自动扣减，跨日不自动改** |
| 6 | `brightness_school` | `quanshu`（7 档：庙旺得利平不陷）/ `modern-v2` | 亮度字与随亮度变化的断语 |
| 7 | `sihua_school` | 通行·飞星 / 全书系 / 中州派 / 北派 / 飞星派 / 透派 | 四化基表差异 |
| 8 | `tianshi_tianshang` | 固定 / 阴阳互换（另含天马基准、火铃三合·南派、空劫命名、大限跨度、星集、三盘） | 星曜落宫与运限 |
| 9 | `zi_chu_huan_ri` | `23:00-next-day`（默认，全系统统一）/ `00:00-next-day` | 五系统日柱一致性 |
| 10 | `judging_basis` | `score-py`（**唯一判档依据**）/ 其他 | 旺衰判档；**本馆禁设第二判档数**（`R-015`） |

> `judging_basis` 是本馆加的第十项，专门锁死定案级规则：透藏加权、票数法、病药直取**不作判档依据**；判档与取用同链（身弱印旺先取比劫不取印）。**口径卡不是给「双口径并列」开后门。**

## 四、跨成员口径冲突检出（交叉印证前置门禁）

`kauding.py check A.json B.json` 比较两卡共用的基础开关：`calendar`、`hour_index`、`true_solar_time`、`late_zishi`、`leap_month`、`dst_cn`、`year_boundary`、`zi_chu_huan_ri`、`timezone`。

| 结果 | 处置 |
|---|---|
| 全部一致 | 允许进入交叉印证册，按 `60`「一致加权／分歧并列／互补补盲」处理 |
| 任一不同 | `conflict=true`：**交叉印证册只列分歧，禁止加权、禁止写「互相印证」**；写明是哪一项开关分岔、各自结论分别归属哪位成员 |
| 卡缺失 | 视为 `blocked`，该成员结论不进入合参，成品中保留限制说明 |

**这条是本册最硬的规矩。** 它的来源是一个可直接借用的思想：两个技法的晚子时开关不同，则结论不可互证。本馆把它扩展成**所有成员之间的通用门禁**——但它只判口径，**不判谁对谁错**，也不替成员改结论（那是主理人主持交叉核对时的事）。

## 五、排盘七铁律与回归门禁

引自 `ziwei-doushu/scripts/regression/pan-integrity.test.ts` 的断言思想，采样不少于 768 盘（跨年代／月／日／时辰／性别）：

1. 正好 12 宫；2. 12 宫名齐全且唯一（命宫·兄弟·夫妻·子女·财帛·疾厄·迁移·仆役·官禄·田宅·福德·父母）；3. 地支 0–11 各且仅一次；4. 命宫唯一；5. **逆时针排布**：第 k 宫地支 = `(命宫地支 − k + 12) % 12`；6. 机梁同宫只可能辰(4)／戌(10);7. **紫府对称**：`(紫微 branch + 天府 branch) % 12 === 4`。

配套断言清单（本馆自建时按此顺序补齐）：日期存在性拒绝、立春换年边界、夏令时逐日、真太阳时 6 个早晚子时样例、闰月四口径神谕表、时辰索引边界、同宫双四化、名人时辰一致性、四化白名单合法性、格局四化加权。

**回归纪律（接 `xuanjian-evolve`）**：新增一层引擎能力，就往回归基准加一个维度；跑不动的维度报「未回归」，**不许并入通过**。口径变更必须同时声明「历史结论需重算复核」（见 `OB98` §4），归档结论绑定 `engine_version` + 口径卡 hash。

## 六、派单流程（主理人动作，顺序不可颠倒）

```
① 归一输入包 → ② 生成口径卡（本馆默认档，或用户指定档）
→ ③ 分发给各成员（只发本门所需的卡字段，不发他人结论）
→ ④ 成员各自独立出结论 + 内部结果卡（99 §3）
→ ⑤ 主理人跑 kauding.py check 做冲突检出
→ ⑥ 主理人主持交叉核对（唯一互通时机）
→ ⑦ 收束成品 → ⑧ source_gate.py 发出前机械核对
```

**不改的三件事**：紫微评测仍走「①命宫定性（文官/武官 → 公职/私企 → 自己干/合作）②身宫影响 ③流年大运全盘」三步；完整报告仍按 `61` 出四册九项；旺衰仍只报 `score.py` 一个数。口径卡只是给这些流程**加上可核对的元数据**。
