# 99 · 合参边界与结构化输出契约

> 本册是**定案级规则「各安其位、各司其职」的工程化说明**。思想来源：`solplum/high-confidence-mingli-skill` 三段式、`yuan` 内部结果卡与输出契约、`Horosa` sections/依据卡/挂载池、`horosa-skill` 的跨技法口径冲突检出。**所有实现自撰。**

## 一、定案级规则复述（不可改）

> 成员只做自己专长那条线，不跨线作答：紫微归斗枢、四柱归知微、相归明相、宅归青囊、卦归观象、奇门择日黄历归司辰、取名归正名、合婚归赤绳、梦归南柯、医归南阳。哪一条线的结论只能由对应成员出，别的成员不许抢答、不许替读盘。**唯一互通时机＝交叉核对**（主理人主持），且**成员各自独立出完结论后才允许互通**；派单时不得让成员知道他人结论，独立性是合参有效的前提。

## 二、三段式合参（唯一合法顺序）

借 `high-confidence-mingli-skill` §9.5 的三段式（它明确「三盘各自独立分析」），映射到本馆：

```
段一 · 各成员独立出 assertion
   { statement, citation, domain, direction, member, status, evidence }
   单盘论断不标置信星级——它的可信度来自典籍出处与引擎盘面
段二 · 唯一互通时机：主理人主持交叉核对
   先跑 kauding.py check → 口径冲突只列分歧、禁止加权
   再做 60 的「一致加权／分歧并列／互补补盲」
   ⭐/置信度只标在「盘与盘之间的关联结论」上，内部可见、对外不曝光
段三 · 主理人收束成品
   按 61 出四册九项 + 用忌神落地；显式标注依据成员与分歧处置
```

**所有命题都是 ⚠️ 或 ❌ 时，直接说「不匹配」，不硬凑、不编。**

## 三、内部结果卡（成员交主理人，不直接给用户）

```json
{
  "member": "斗枢",
  "method": "ziwei",
  "status": "runnable|partial|blocked",
  "facts": { "...": "只放工具产出的确定性事实" },
  "interpretation": { "...": "只放本门解读，标〔本馆归纳〕处" },
  "confidence": "内部，不对外",
  "blockers": ["缺出生地，真太阳时未校"],
  "evidence": ["册号/出处/段落号"],
  "kauding_hash": "口径卡 hash"
}
```

- `facts` 与 `interpretation` **必须分栏**，不得混写；经验解读不包装成科学证明。
- `partial` / `blocked` **显式声明为限制**，不许用缺失事实拼凑断语、不许降级成「大概如此」；主理人看到非 `runnable`，须在成品中保留该限制说明。
- 结果卡是**内部件**：对用户隐藏过程叙述，对主理人**强制留痕**（这是 C3 的分层处理，见 §5）。
- 成员不得在结果卡里写他人领域的判断；主理人发现越级，退回该成员重写，不代为补写。

## 四、结构化输出契约

每次技法输出同时产「人读正文」与「结构化快照」，模型只能从快照取数，**不得从自由文本反推结构**：

```json
{
  "sections": [
    { "title": "", "body": "", "structured_data": {}, "member": "", "evidence": [] }
  ],
  "selected_sections": [],
  "provenance": { "kauding_hash": "", "engine_version": "", "source_refs": [] },
  "technique_card": { "技法名": "", "流派口径": "", "关键开关": {}, "算源声明": "", "运行实测": "", "段落完整性": "", "版本链": "" }
}
```

| 规矩 | 内容 |
|---|---|
| 单一构造点 | 所有技法、所有模型、所有导出格式共用同一份 `sections[]`；禁止在 prompt 里让模型自行拼 JSON |
| 六格式同源 | `md / html / json / csv / pdf / docx` 由同一份 `sections[]` 渲染，不为不同格式另写内容逻辑 |
| 按段过滤 | 导出条件写进请求，`selected_sections` 与实际内容一致 |
| 方法报告分轨 | 方法报告只含机器元数据（用了谁、什么口径、版本链、段落完整性）；咨询报告是终稿，两者不互相混入 |
| 算源 vs 实测 | 分别落库并比对，不符时显式亮警「结果请谨慎采信」 |
| 个人口径注入 | 用户的流派偏好／输出格式偏好走独立注入通道，默认关闭、开启可审计，**不写进模型正文** |
| 依据卡带出处 | 引教义必带出处；无出处的解读明说「此为通则推理」——这是反 Barnum 效应的第一机制 |

**八段版式契约**（`资料确认 / 结论 / 事业 / 财运 / 感情 / 五年断事 / 建议` 一类）只作用于**轻量成品**；凡完整报告一律以 `61` 四册九项为准，**不得用八段契约替换四册**。两轨并存，判据是用户有没有说「完整分析／详细报告／全面评测」。

## 五、`yuan` 的六点冲突与五点可借（写入专家包前必读）

### 可借（不触碰分工）

| 可借点 | 落点 |
|---|---|
| 统一输入包 + 单一口径裁定 | `OB96` §2，**收归主理人**，不下放成员 |
| `runnable/partial/blocked` 状态自报 | §3 结果卡，属成员自检 |
| deterministic facts vs heuristic reading 分层 | §3 分栏，成员内部纪律 |
| 内部结果卡（含 `confidence`/`evidence`） | §3，**但这两项必须保留给主理人，不得丢弃** |
| 输出版式契约 + 三档交付档位 | §4，只是版式；**切换权归主理人**，成员无权自行切档 |

### 禁止照搬（六点）

| # | `yuan` 做法 | 冲突 |
|---|---|---|
| C1 | **一个总 skill 亲自跑六法**，「每次完整分析优先覆盖这六个方法」 | 单一执行体跨线抢答，直接违反「成员只做自己专长那条线」 |
| C2 | 执行流程「先归一到六维 → 先生成 `final_verdict` → **第 6 步才做一致性判断**」 | 交叉执行体不是主理人，且**结论先于核对**；违反「成员须先独立出完结论」 |
| C3 | 明确禁止暴露「跨法一致性／分歧与置信度」 | 本馆交叉核对的产物**就是分歧清单**，主理人必须持有；**只能对用户隐藏，不得对主理人隐藏** |
| C4 | 统一渲染成无来源的「结论／事业／财运／感情」 | 抹掉专长归责，等于整合者代替成员发言；本馆结论须标依据成员与分歧处置 |
| C5 | `assertiveness=high` 允许「哪一年**一定**发生什么」 | 与禁用绝对化、不编造具体应期冲突，**不迁移且明令禁止** |
| C6 | README 列三种渲染模式、SKILL.md 只有两种；README 把已实现的运行时参数仍列为待办 | 直接抄会引入「三模式 vs 两模式」口径分裂；**只以 SKILL.md 为实现依据** |

> 真一「哪里判断一致、哪里说法冲突，就应该讲清楚」在**理念**上合拍，但它是把四派融进同一个 27B 权重（单执行体），**只借态度，不借架构**。同理 `yuan` 的「≥3 个 runnable 来源」可降格为**主理人启动交叉核对的前置门禁**（结果卡齐了才开会），一致性判断本身只能在会后由主理人做出。

## 六、技法挂载池（主理人派单用）

- 技法注册为「可挂载能力」，每项声明 `requires ∈ {chart, timepoint, two-charts, any}` 与本门 `techniqueKeys`；挂载前按当前上下文标 `available / why`，可用项排前、灰项就地灰显并给原因码（如「需命盘案例」「先挂案例」）。
- **挂载池是全技法并集，禁止按当前页截断**；点名挂载支持中文子串／英文键／拼音；技法在全集但当前案例不可挂时，返回显式提示「技法『X』不适用于当前案例，未挂载」，不许静默剔除。
- 两遍解析：先解析案例引用确定来源，再按切换后的来源判技法可用性。
- 设置分面（盘面／挂载／应用／典籍／技法），改设置走 `describe → get → set` 并给写前 diff；挂载状态可持久化、可撤销；写入需确认，**删除永不开放**。
- **本馆加一条**：挂载池只决定「叫谁」，不改「谁答什么」。派单时仍不得让成员看到他人结论。

## 七、可视化边界

- 可借：把大运／流年做成时间轴、双轨联动、按技法／页签过滤段导出、3D 天象仅作教学展示。
- **不迁移 `miounet11/life-kline` 的 AI 打分 K 线**：其分值由 AI 生成而非确定性引擎、核心提示词加密、含「加密货币交易运势／暴富流年预测／交易风格建议」，属合规高风险，且与本馆「命给范围不给结论」相悖。
- 若做命途可视化，**纵轴只能是确定性量**（如 `score.py` 档位、大运干支、口径卡记录的运限层级），须标注「示意，非预测值」；**不许把 AI 生成的吉凶分数画成 K 线**，不许出现「暴富流年」类标签。
- `DeeplumnClaw/human-trajectory-model` 未核实到（404），不引用其模型定义。

## 八、交付治理

写入需审批档位 `never | on-request | read-only`；长调用须有进度与取消；离线优先，核心排盘不依赖网络；所有输出附 `OB97` §7 固定免责与 AI 生成标识；示例与评测数据一律虚构。
