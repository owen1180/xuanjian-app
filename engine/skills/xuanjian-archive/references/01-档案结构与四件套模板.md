# 档案结构与四件套模板

## 一、目录骨架

```
命理档案/                        ← 档案根目录，默认建在工作区根下
├── 档案索引.html                 ← 唯一入口：案例卡片 + 交叉结论表 + 待验证总账
├── 归档模板.md                   ← 本文件所在宗旨的索引与六步清单（可选留存）
├── 方法论/
│   └── 断法规则库.md             ← 经验沉淀：规则表 + 易错清单 + 待验证总账
└── 八字库/
    └── <四柱连写>/               ← 档号即目录名，全库唯一
        ├── 档案卡片.md            ← 命理分析本体，**全档只有一份**
        ├── 命主记录.md            ← 同一八字下的各位命主
        ├── 分析记录.md            ← 历次测算的追加式流水
        └── 命盘分析报告.html      ← 交付给用户的完整长报告
```

**命名约定**：目录名只用四柱八个汉字（时辰待补则三柱 +「待补时」），不写姓名不写年份——名字会错、年份会重复，只有四柱不会变。

**关系圈与档号分开记**：档号说明「这造是什么盘」，分组说明「这人和我什么关系」。
两者写在不同地方——档号进目录名，分组进 `档案索引.json` 与卡片基本信息（见 §七）。

## 二、为什么是这四件套

| 文件 | 回答什么问题 | 更新频率 |
|---|---|---|
| 档案卡片.md | 这一造的命理本体是什么 | 结论有变才改，全档一份 |
| 命主记录.md | 这个八字下都有谁 | 撞盘时才加一行 |
| 分析记录.md | 这一造一共算过几次、每次多说了什么 | 每次测算追加一条 |
| 命盘分析报告.html | 给命主看的那份完整版 | 随卡片同步 |

分开的理由：**命理本体人人相同，命主人人不同，每次测算的增量各不相同**。三件事混在一个文件里，迟早要拆。

## 三、档案卡片模板（八节）

```markdown
# 档案卡片 · <四柱>（<乾／坤>造）

> 归档日期：YYYY-MM-DD ｜ 完整报告：[命盘分析报告.html](命盘分析报告.html) ｜ 关联案例：<相对路径互链>

## 一、基本信息与核盘
- 出生：YYYY年M月D日（农历X年X月X日）· 时刻 · 出生地
- 真太阳时修正：±X分 → 仍属X时（若不修正会错则写明）
- 核盘方式：万年历库独立复算，与成员结论一致／不一致处：……

## 二、四柱与十神
| 年柱 | 月柱 | 日柱 | 时柱 |
（注明日主、藏干、十神、纳音）

## 三、格局与用神
打分：X分 → 层次；病在何处；扶抑用神与调候是否一致；用神级别。

## 四、八项评分
健康／学业／事业／财富／感情／子女／父母／配偶，各给分数与一句定论。

## 五、大运表
| 大运 | 岁 | 公元起止 | 要点 |
（只列关键的，不流水账）

## 六、关键年份
关口年、最佳年、节点年，分别注明为何。

## 七、关联案例
与其他档号的六亲互链与交叉结论（如夫／妻／子三盘如何互证）。

## 八、待验证事项
| 议题 | 命理解读 | 真实情况 | 状态 |
（真实情况一栏留空待回填，回填后更新置信度）
```

## 四、命主记录模板（每人一行）

```markdown
# 命主记录 · <四柱>

| 序号 | 性别 | 出生时刻 | 出生地 | 家族关联 | 备注 |
|---|---|---|---|---|---|
| 1 | 女 | 卯时 6:20 | 桂林 | 主案本人 | 首次测算日期 |

> 同一八字者的格局用神必然相同，但出生地（真太阳时）、性别（大运顺逆）、实际履历三者不同，
> 差异写在本表而不改动《档案卡片.md》，以免串案。
```

## 五、分析记录模板（追加式流水）

```markdown
# 分析记录 · <四柱>

## 第 N 次 · YYYY-MM-DD · <议题>
- 用户问：<原话摘要>
- 所属命主：<序号>
- 结论增量：<比上次多知道了什么，不许复述旧结论>
- 采用规则：R-xx、R-xx
- 置信度变化：<哪项由中升为高>
```

**纪律**：追加不覆盖。历史判断即使后来被推翻，也保留原文并在下方补订正条——订正记录本身就是最有价值的规则来源。

## 六、索引页要求

`档案索引.html` 是唯一入口，必须含四块：

1. **计数条**：八字档数、命主数、累计分析次数、规则条数（每次归档同步刷新）
2. **档号卡片**：每档一张卡，列四柱、性别、角色标签（如"主案之夫"）、格局用神一句话、互证要点、卡片链接
3. **交叉结论表**：跨档互证的对照（哪一盘的哪颗星，对应哪一盘的哪颗星，合起来说明什么）
4. **待验证总账**：汇总各档待回填的议题，便于事后校准

兼作查重工具使用：加一段"合并规则"提示框，说明「八字相同合并、时辰不同另立」。

## 七、分组：这盘是谁的（v1.72.0）

档号只回答「什么盘」，回答不了「和谁的关系」。实际最先问的偏偏是后者：
「给我同事看过的那盘档号多少」「今年客户几档」「名人那几档别和客户混」。

### 七个分组（固定，不许自创）

**家人／朋友／同学／同事／客户／名人／其他**

两条不是随手分的：

- **名人单列**，为了和客户分开——名人是公开盘，可引用、可写案例；客户是私人盘，
  进不了对外材料。混在一起，迟早有人拿客户盘当案例讲。
- **`未分组` 不是 `其他`**：迁移时读不出分组的档进「未分组」，必须逐档补。
  **默认值会掩盖没做的事**——一律塞进「其他」，看着分类完成，其实一条没分。

**七类之外要加一类，走索引不改代码**：馆主自己的盘（本造）不属任何一类——
归「家人」不对，归「其他」等于没分。在 `档案索引.json` 的 `groups` 里加一条
（如 `"本人"`），`groups.py 登记 --分组 本人` 就收得下；改完跑一次 `迁移` 重建。
**口子只开给「加一类」**：自创同义类（「亲戚」「亲友」）仍判错——同义类一多，
统计就散了。

### 记在哪

| 位置 | 内容 | 谁读 |
|---|---|---|
| `八字库/<档号>/档案卡片.md` | `- 分组：客户`、`- 称呼：张先生` | 人；跟着档走 |
| `命理档案/档案索引.json` | 每档一条：档号、分组、称呼、更新 | 机器；清单／统计／按组筛 |

**卡片是主，索引是缓存。** 卡片改过而索引对不上时，以卡片为准重写索引
（`groups.py 重建`）。反过来拿索引覆盖卡片，等于用缓存冲掉原件。

### 命令

```
python3 groups.py 登记 命理档案 丁酉己酉丙午辛卯 --分组 客户 --称呼 "张先生"
python3 groups.py 清单 命理档案 --分组 客户
python3 groups.py 统计 命理档案
python3 groups.py 迁移 命理档案        # 扫全库读卡片，读不出的标「未分组」
python3 groups.py 重建 命理档案        # 以卡片为准重写索引
```

`find_chart.py` 命中时会带出分组与称呼；**同组撞盘**额外警告——
同一片关系圈里出现同一个八字，多半是**同一个人被重复归档**，不是「巧合同盘」，
要先比对性别、出生地、称呼，再决定追加还是另立。

### 建档时的动作顺序

1. `find_chart.py` 查重（命中即追加，不新建）
2. 建档四件套
3. **`groups.py 登记 … --分组 X`** —— 漏这一步，档就成了「未分组」
4. `audit_charts.py` 复算四柱、`check_cn.py` 纯中文
