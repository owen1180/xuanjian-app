# 规则编号回填与运行时台账

> 交付前不记一次，复盘时全是回忆。**这份台账管的不是算得准不准，是"该用的规则到底用了没有"。**

## 一、它解决什么

`03` 管的是"经验怎么变成规则"，本册管的是**规则有没有真的被执行**。两者是一前一后：`03` 让规则变多，本册让规则变实。

过去只有两种状态：规则写在册子里，报告交出去了，中间有没有用上全凭人自觉。现在多一道留痕：

```
交付前 → 过闸门 + 记「召回了哪些 / 实际引用了哪些」
交付后 → 用户给实情 → 回填到规则 ID
月末   → 汇总成收录报告 → 该补信号的补、该升版的升
```

## 二、三个动作

### 1. 记录（每次交付前必跑）

```bash
python3 scripts/kb_ledger.py 记录 \
  --档号 丁酉己酉丙午辛卯 --议题 事业 \
  --问 "我这步运事业如何" \
  --稿 "<最终要交给用户的正文>" \
  --用规则 K039,K043
```

- `--稿` 传**最终稿**，工具会拿它过 `xuanjian-kb/scripts/kb_gate.py` 的闸门。
- `--用规则` 填报告正文里实际标注或遵从的编号，不是"可能相关的"。
- **闸门 BLOCK 时本命令非零退出，视为不得交付**。台账照样留痕，便于复盘为何越界。
- 编号写错（如 `K39`）会告警并按无效编号记，不静默吞掉。

### 2. 回填（用户给出实情后）

```bash
python3 scripts/kb_ledger.py 回填 \
  --档号 丁酉己酉丙午辛卯 --议题 事业 \
  --规则 K039,K043 --结果 已验证 --说明 "次年确获晋升，力度与判据相符"
```

`--结果` 只取 `已验证` / `已修正` / `未验证` 三值：

| 结果 | 含义 | 对规则的影响 |
|---|---|---|
| 已验证 | 事实与判读同向 | 累计 ≥2 次且无订正，可升版（对齐 `03` 的中→高靠事实回填） |
| 已修正 | 事实相反或偏得远 | 记入订正，规则不删，另立修正条（编号只增不改） |
| 未验证 | 尚不清楚或未发生 | 不计入升级，保留待观察 |

### 3. 汇总（阶段性跑）

```bash
python3 scripts/kb_ledger.py 汇总 --输出 方法论/kb_规则收录报告.md
```

输出逐条规则的召回／引用／拦截／验证计数，以及三条结论。**存在"触发失效"规则时非零退出**，提醒去收紧触发。

## 三、两个反向指标（本册的重点）

大多数人只看"拦住了几次"，真正值钱的是两个失配方向：

| 指标 | 现象 | 含义 | 处置 |
|---|---|---|---|
| **召回未引用** | 闸门认为该用，报告里没用 | 知识在场却没落地：或触发信号过宽，或人写报告时漏了 | 先看是否误召回；确属该用未用，把人这一环补上 |
| **引用未召回** | 人用了，闸门没认出来 | 机器漏看，或人过度谨慎 | **必须人工裁定，不许一律加词** |

**「引用未召回」的裁定纪律（血泪一条）**：

一次真实台账里，四条规则同时报"引用未召回"，看着像四个漏洞。逐条看完只有一条是真缺口：

- **K003 六亲**——用户问"我和父亲缘分如何"，"父亲""缘分"是六亲的日常说法，却不在召回词里 → **真缺口，补词**。
- **K024 就医 / K039 用神 / K043 档位**——问的是父亲缘分与事业走势，既没有健康症状，也没有"必发"这类断语，是**写报告的人顺手多标了编号** → 不是机器的问题。

若当时闭眼四条都加词，K024 会因为"父亲"二字在每次谈六亲时都跳到闸门前排，K039 会因为"事业"二字把每条事业咨询都判成需要封顶——**噪声进来容易，清出去要很久**。

所以规矩是：**先判是"机器漏看"还是"人标多了"，只有前者才动召回词；动完必须跑 `regress.py 检查`，报漂移要能说清是订正还是改坏。**

## 四、台账放哪、不进哪

| 项 | 规矩 |
|---|---|
| 默认位置 | `命理档案/方法论/kb_运行时台账.jsonl`（随档案走，可用 `--台账` 或环境变量 `XUANJIAN_LEDGER` 覆盖） |
| 写入方式 | **只追加**，不改写历史行；一条测算一行、一次回填一行 |
| 不进档 | 台账是运行观测数据，**不写进《档案卡片》正文**，避免污染命理结论 |
| 隐私 | `--稿` 只存前 120 字摘要；`--问` 存用户原话，涉及第三人时按 `01` 的隐私最小化处理 |

## 五、与其它册子的关系

| 册子 | 分工 |
|---|---|
| `03-规则沉淀与置信度` | 规则怎么编号、置信度怎么定；本册提供**事实回填的原始数据** |
| `xuanjian-kb/57-运行时强校验闸门` | 闸门拦什么、怎么拦；本册负责**把它拦过的与放过的都记下来** |
| `xuanjian-evolve/regress.py` | 改引擎后的行为回归；本册的「引用未召回」修复后必跑 |
| `04-交付前自检清单` | 交付前逐项自查；本册的 `记录` 是其中"过闸门"一项的落地工具 |

## 六、一句话

**召回率再高，不引用等于零；拦截再准，不回填等于没验过。** 台账的作用是让这两件事都留下痕迹。
