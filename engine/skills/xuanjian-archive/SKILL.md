# 命理档案操作规程

> 「一次测算是答案，一叠档案才是学问。」——本馆规矩：**每算完一造，必须留档**。

这套规程解决三件事：**不复算重活**（查重）、**不复述旧话**（同盘合并）、**不重复犯错**（沉淀规则）。

## 一、什么时候调它

| 场景 | 动作 |
|---|---|
| 用户给出一个新八字要测算 | 先导 `02` 查重，**已有档就追加、没档才新建** |
| 一次测算交付完毕 | 走一遍第三节的**六步收尾**，由主理人执行 |
| 用户说"以前算过某八字""帮我整理一下""复盘一下" | 按 `02` 检索索引与档号 |
| 用户回填了真实发生的事 | 按 `03` 做**事实回填**，提升相关规则置信度 |
| 交付报告前 | 跑一遍 `scripts/check_cn.py` 与第四节自检清单 |
| 要确认"该用的规则真的用了"、或给规则留收录依据 | 用 `scripts/kb_ledger.py 记录`：过闸门 + 记召回与引用，见 `05` |
| **要引用整本书的原文、或判断某本书能不能引** | 查 `命理档案/引证库/索引.json`（`quote_index.py 建` 生成）：四档 `可逐字引`／`仅指认`／`近空`／`散图`。**整本书不拆句进册页**；扫描件未 OCR 只许指认，不许写引号内原文（规程见 `TR116` §四） |
| **排盘引擎改过、升级过、或修了 bug** | 跑 `scripts/audit_charts.py` 回查存量：抽每张卡片的出生信息，用现引擎重排，与目录名上的四柱逐柱比对。**改了引擎不重算旧账，等于旧错留在档案里**（规程见 `TR113`） |

## 二、档号规则（铁律）

**档案以「四柱（八字）」为唯一键，不以「某个人」为键。**

```
档号 = 四柱连写，如 丁酉己酉丙午辛卯
时辰不明 → 前三柱 + 「待补时」后缀，如 庚寅己卯戊午待补时
```

| 情形 | 判定 | 处置 |
|---|---|---|
| 四柱八个字完全相同 | **同一八字** | 并入一档，命理分析只写一份，新增命主登记到《命主记录.md》 |
| 同年同月同日而时辰不同 | **不同八字** | 另立新档，两者互链注明"同日异时" |
| 同一人时辰后补齐全 | **档升级** | 重命名目录，同步修正索引页与关联卡片的两处链接 |

**为什么必须这样**：同一八字者的格局、用神、十神结构必然相同，分析重复写两份纯属浪费且容易前后矛盾；但**出生地（真太阳时）、性别（大运顺逆）、实际履历**三者因人而异，所以命主要分开登记，否则串案。

## 三、收尾六步（每次测算必走）

```
① 核盘校验 → ② 查重定位 → ③ 写/续档案 → ④ 更新索引 → ⑤ 事实回填与沉淀规则 → ⑥ 当日日志
```

1. **核盘校验**：用 `scripts/pillar.py` 独立算一遍四柱、农历、节气与起运，与成员报上来的核对；不一致必须先查清再落笔。
2. **查重定位**：用 `scripts/find_chart.py` 按四柱查档，决定新建还是追加。**禁止重复建档。**
3. **写/续档案**：新建走第 2 节模板；已有档 → 命理结论更新《档案卡片.md》，新命主加《命主记录.md》，本次测算**追加**一条到《分析记录.md》（追加式，不覆盖历史）。
4. **更新索引**：档数、命主数、分析次数、规则条数四项计数必须同步刷新；跨档结论写入交叉表。
5. **事实回填与规则沉淀**：用户告知实情后回填到卡片「待验证事项」表；若某条判读在其命盘上得到验证写入 `方法论/断法规则库.md`，按 `03` 编号升级置信度。**回填的同时用 `scripts/kb_ledger.py 回填` 把事实验证贴到规则编号上**（`05`），别只写卡片不喂台账。
6. **当日日志**：向工作区当日记录追加一行，写明新增/更新了什么。

## 四、脚本

| 脚本 | 用法 | 作用 |
|---|---|---|
| `scripts/pillar.py` | `pillar.py 1957 10 1 --hour 6 --minute 20 --lon 110.29 --sex 女` | 排盘核盘：四柱、农历、节气起运、五行个数；缺时辰也能算三柱与大运 |
| `scripts/find_chart.py` | `find_chart.py 命理档案 丁酉己酉丙午辛卯` | 查重：精确匹配同四柱、缺时柱模糊匹配、列出同日前六柱 |
| `scripts/check_cn.py` | `check_cn.py 命理档案` | 交付自检：扫描 `.md`／`.html` 可见正文里的英文残留，非零退出码表示不通过 |
| `scripts/init_library.py` | `init_library.py 命理档案` | 建库：生成目录骨架并可选灌入模板 |
| `scripts/kb_ledger.py` | `kb_ledger.py 记录 --档号 … --问 … --稿 … --用规则 K039,K043` | 运行时台账：交付前过闸门并记"召回／引用"，用户回填后 `回填`，随时 `汇总` 出收录报告（`05`） |

> 依赖：万年历库 `sxtwl`；缺库时先安装，再用工作区现有的解释器运行。

## 五、边界

1. **绝不虚构生辰补盘**。缺时辰就标「待补时」，大运仍可精算（年干定顺逆、月柱定序列），但要写明局限。
2. **绝不顺用户的"应该有"改判**。用户说"我应该是卯时吧"，只做假设分支，不定论。
3. **隐私最小化**。档案里写命理不强写姓名住址；涉及第三人的盘，只在必要范围内记录，并注明来源。
4. **健康与生死一律转风险语言**，归档文字同样适用：写"关口""宜有人陪伴"，不写"死""夭""必凶"。
5. **交付物必须纯中文**，交付前必跑 `check_cn.py`；网页标签名属结构件，不计入。

## 六、与桌面排盘工具同源（铁律）

「玄鉴命理馆排盘工具」（`/Applications/玄鉴命理馆排盘工具.app`，当前 1.5.0）**与本规程写同一份档案库**：

```
/Users/haoqing/WorkBuddy/2026-10-22-16-06-26/.workbuddy/bazi-archive/registry.json
```

| 事项 | 口径 |
|---|---|
| 唯一键 | 八字（四柱连写）。桌面端排盘、命令行工具 批量、本规程手工建档，三处都按八字查重，同盘合并、多次测算追加 |
| 谁先谁后 | 引擎写入的是**初判**；库中已有人工定案的字段，一律保留人工结论，冲突只记「待复核」，**不静默覆盖** |
| 渲染出口 | 主库单一渲染源，档案卡片／总索引／命造页由同一套模板产出，不各写一份 |
| 成员动作 | 看到「待复核」就去裁定。别绕过闸门直接改库里的结论字段 |

> 桌面端会自动完成①核盘校验②查重定位③写／续档案④更新索引，人只需做⑤事实回填与规则沉淀、⑥当日日志。
> 手工跑本规程时，六步一个都不能省。
