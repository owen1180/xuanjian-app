## 1. Description

玄鉴命理馆的分诊入口：先判这一问走哪条线、缺什么资料、先补哪一步，再交给对应成员；本 skill 只做分流与资料检查，不排盘、不出断语。触发词：四柱排盘、紫微斗数、六爻起卦、梅花易数、时家奇门、风水堪舆、合婚、择日、取名、解梦、手相面相、流年大运、用神落地、盘面截图、户型坐向、健康关口、报告规格、口径卡、册页出处。

## 2. Publisher

玄鉴命理馆（本馆自撰、零依赖）。主页与交付包见专家包根目录 `README.md`；本卡相对路径 `skills/xuanjian-mingli-entry/skill-card.md`。

## 4. Use Case

独立分发的轻量入口：用户只丢来一句问题、一张图或一份不全的资料时，先判断「该叫谁、还缺什么」，再决定是否升级为完整专家团作业。典型用法一句话：**「我这个情况该找哪条线看，先补什么？」**

## 5. Deployment Geography

面向简体中文语境，适用地域与法域以使用者所在地为准。本 skill 不提供医疗、法律、投资、心理诊断；涉及这些领域一律转专业人士。平台合规：触发词已按 `KB102` §2.4 移除第三档泛化词，使用前仍应按实际投放平台复核违禁词表。

## 6. Known Risks and Mitigations

| 风险 | 缓解措施（成对出现，不单写风险） |
|---|---|
| 入口误判，把该走重量双盘的一问当成轻量单线 | 四问定类 + 路由速表；凡「生辰＋想知一生／完整分析」一律升级重量双线，四柱必配紫微，两盘独立出结论再交叉 |
| 资料不全就硬凑精排盘 | `KB100` S/A/B/C 分级；时辰未知给 13 个候选槽并列并显式降级，主理人不静默默认 |
| 入口自己下了断语，越过成员 | 本 skill 输出契约只三件事（走哪条线／缺什么／先做什么）；产出过 `source_gate.py` 与 `kb_gate.py` 双闸 |
| 涉及健康时越界成诊断或终点判断 | 红线速记 + `46` §1.1 合规对照表 + 出口禁词表；给动作不给结果，急症转医生 |
| 泛化触发词造成误触发与平台限流 | 触发词只留体系词与场景词，第三档一个不写；description 与触发词表一起改，不设独立 keywords 字段 |
| 用户上传他人照片或生物识别资料 | `KB101`：先确认对方知情，只做与提问相关的最小解读，不落盘、不外呼、不进排盘入参 |

## 8. Output Type / Format / Parameters

- **输出形态**：中文结构化短文本（Markdown），不是命盘、不是报告、不是 JSON 接口。
- **格式**：三件事固定顺序 —— ① 走哪条线（轻量／重量、成员 ID）② 还缺什么（S/A/B/C 级别与缺项）③ 先做什么（补资料或升级路径）。分流结论标〔本馆归纳〕，附覆盖范围自评（充分／不足／不覆盖）。
- **参数维度**：输入类型（生辰／盘面／照片／户型／事件／问题）、三才层级、资料完备度、是否需多成员合参、是否涉及健康或第三方隐私。
- **不产出**：排盘结果、判档分数、断语、合参结论、口径卡。
