# 一百零二、技能卡规范与触发词一致性纪律

> 本册规定玄鉴作为 **skill 资产**对外分发的规范：技能卡怎么写、触发词怎么配、元数据怎么保持自洽。
> 背景：对标包「命理大师」在 SKILL.md 里声明已移除「算命／占卜／命理」等过宽泛触发词，**但 package.json 的 keywords 数组里这些词一个没删**——元数据与实际行为脱节，是典型的工程事故。本册专为防这一类事故而立。

---

## 一、技能卡（skill-card.md）规范

每个对外分发的 skill 都要有一张技能卡。**技能卡是给「不了解这个 skill 的人」看的说明书**，不是给使用者看的说明书。

### 必填八项

| # | 项目 | 要求 |
|---|---|---|
| 1 | **Description** | 一句话说清「它做什么、覆盖哪些范围、输出什么形态、有什么边界」 |
| 2 | **Publisher** | 发布者标识与主页链接 |
| 3 | **License / Terms** | 明确授权条款；引用第三方语料须单独标注原授权 |
| 4 | **Use Case** | 谁在什么场景下用它、典型用法一句话 |
| 5 | **Deployment Geography** | 适用地域与法域限制 |
| 6 | **Known Risks and Mitigations** | **风险条目 + 对应缓解措施成对出现**，不得只写风险 |
| 7 | **Reference(s)** | 册页/文档清单，带相对路径 |
| 8 | **Output Type / Format / Parameters** | 输出形态、格式、参数维度 |

### 可选但推荐

| 项目 | 要求 |
|---|---|
| **Ethical Considerations** | 使用者部署前应自行评估的伦理事项 |
| **Skill Version(s)** | 版本号与来源证据 |
| **Output Properties** | 输出附加属性（如是否引用本地脚本、是否依赖外部服务） |

### 关键约束

**① 风险条目必须配缓解措施，不允许只列风险不写对策。**

反例（不合格）：
> Risk: 本技能可能存储敏感出生信息。

正例（合格）：
> Risk: 本技能会在本机存储用户主动提交的出生信息与可选的家庭成员信息。
> Mitigation: 仅在用户接受本地留存的前提下安装；定期检查已存档案；使用档案删除功能，需要彻底清除时使用物理删除。

**② 技能卡不写「准确率」「有效率」「百分之多少灵」等任何量化宣称。** 这一条与 `KB99` 的措辞规范同源，也直接对应平台审核对「宣称」的敏感。

**③ 技能卡的 Description 与 SKILL.md 的 description 必须一致。** 两者是同一份事实的两种呈现，不允许一个说「全体系解读」另一个说「快速查询」。

## 二、触发词一致性纪律（**最重要的一条**）

### 2.1 规则

> **description 里出现的每一个触发词，必须在 keywords 里出现；keywords 里出现的每一个词，必须在 description 里有对应语境。**
> **两者不一致时，以 description 为准，并立刻修正 keywords。**

### 2.2 为什么这条是硬规则

| 机制 | 说明 |
|---|---|
| **检索层** | 平台/运行时按 keywords 与 description 做匹配召回。不一致 = 一半的词白写，另一半误触 |
| **误触发** | 过宽泛的词（算命、占卜、fortune telling）会在**用户完全没要求占卜**的普通对话里被激活，这是最真实的用户伤害 |
| **合规层** | 抖红等平台把「算命/占卜/转运」列为违禁词，命中即限流或封禁。keywords 是被检索的字段，**写在 keywords 里等于主动暴露** |
| **信任层** | 声明了不做什么，却在检索字段里留着那些词，等于自相矛盾 |

### 2.3 触发词的三类分法

| 类型 | 定义 | 处理 |
|---|---|---|
| **体系词** | 八字、四柱、紫微斗数、奇门遁甲、六爻、梅花易数 | **保留**——精确指向，是专业用户的主要搜索入口 |
| **场景词** | 排盘、流年、大运、合婚、择日、取名、五行、用神 | **保留**——同上，且带意图信息 |
| **泛化词** | 算命、占卜、看相、风水、转运、命理、fortune telling、astrology | **谨慎处理**，见 §2.4 |

### 2.4 泛化词的三档处理

```
第一档 · 可保留（泛化但无害）
  风水堪舆、起名取名、星座占星（西法体系专属）、易经周易
  → 这些词在专业语境下有明确所指，不是玄学诈骗信号

第二档 · 加限定后保留
  「算命」→「传统命理排盘」（保留体系指向，去掉诈骗联想）
  「占卜」→「六爻起卦／梅花易数」（落到具体体系）
  「转运」→「五行喜用与生活调整」
  「命理」→「四柱／紫微排盘」

第三档 · 移除
  fortune telling、算命大师、灵验、改命、转运符、开光
  → 这类词既是平台红线，也确实会招来错误预期
```

### 2.5 自检脚本（发布前必跑）

```bash
# 1) 提取 description 中的中英文关键词
# 2) 提取 keywords 数组
# 3) 比对：keywords ⊆ description 中出现的词 + 英文别名
# 4) 扫描违禁词表
```

**违禁词扫描表**（社交平台生态通用）：

```
算命  占卜  看相  开光  转运  改运  招财  旺财  旺夫  辟邪
化太岁  符咒  法术  仪式  血光之灾  大凶之兆  逆天改命  斩桃花
玄学  灵验  百分百  绝对  第一  唯一  官方
```

**任一命中 → 发布前必须处理。**

## 三、对外文案的层级纪律

同一个 skill 的三层文案，**必须各自定位、互不越级**：

| 层 | 写给谁 | 写什么 | 不写什么 |
|---|---|---|---|
| **展示描述**（displayDescription） | 目录页的浏览者，一眼扫过 | 一句话说清覆盖范围与形态 | 任何断言、任何量化宣称 |
| **description**（技能说明） | 运行时与检索 | 覆盖范围 + 边界声明 + 触发词 | 触发词之外的营销话术 |
| **body / 正文**（SKILL.md 主体） | 实际使用技能的人 | 方法论、规则、话术、边界细则 | 重复 description 的营销内容 |

### 3.1 展示描述的写法

**长度**：30–60 字（多数平台按 40–50 字校验，超出会截断）。

**句式**：覆盖范围（几个体系）＋ 工作方式（并行研读／交叉校核）＋ 交付形态（可复盘的分析）。

**禁写**：断命式动词（定命、断宅、断事、详批、算准）、量化宣称、绝对化表述、任何"预测/决定"含义。

**正例**：
> 子平、紫微、相法、堪舆、奇门等六路传统术数并行研读，各自独立再交叉校核，输出可复盘的九项分析。

**反例**：
> 八字紫微定命，手相看当下，堪舆断宅，奇门择吉。96% 准确率。

### 3.2 正例与反例对照（玄鉴专用）

| 维度 | ❌ 禁写 | ✅ 应写 |
|---|---|---|
| 命理 | 八字定命 | 四柱排盘与取用 |
| 堪舆 | 断宅吉凶 | 传统居住营建理念分析 |
| 卜 | 断事 | 起卦与卦象取象 |
| 报告 | 本命详批 | 结构化九项分析 |
| 通用 | 算得准 | 可复盘的推演过程 |

## 四、版本与变更纪律

| 变更类型 | 版本号 | 说明 |
|---|---|---|
| 措辞调整、字段增补 | MINOR | 展示文案、描述、关键词调整 |
| 新增册页、脚本 | MINOR | 内容扩充 |
| 规则变更、边界调整 | MAJOR | 措辞规范、分级标准、留存策略变更 |
| 断语口径变更 | MAJOR | 影响既有交付物 |

**每次发布前必须记录**：
1. 改了哪些字段（description / keywords / body / 册页）
2. 是否触发关键词命中变化（**命中变了就必须重跑违禁词扫描**）
3. 是否影响既有交付物口径

## 七、一句话总结

**技能卡是给陌生人看的说明书，keywords 是检索入口，两者说的必须是同一件事。说一套做一套，比说错更伤信任。**
