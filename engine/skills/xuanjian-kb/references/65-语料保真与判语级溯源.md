# 六十五、语料保真与判语级结构化溯源

> 这一册补本馆最缺的一块：**判语级的结构化与可回放溯源**。
> 以前册页是「一段话」，现在要变成「一条条带出处锚点的判语」——谁说的、在哪一分哪一秒、和哪本古籍对得上。
> 方法来自 `Renhuai123/nihai-tianji-corpus`（天纪 4886 条判语，秒级溯源）与 `xiaogege6697/tcm-db`（可审计 SQLite 底座）。
> 引用与许可规程照 `64` §6；证据分层与「不给处方」照 `66`。

## 1. 为什么要这一册

本馆原有 64 册方法论（本轮扩至 67 册），但**判语是散在正文里的**。一个结论"倪师在天纪里讲过"，却常常查不到"哪一讲、哪一分、哪一秒"。
这带来两个隐患：

1. **不可核对**：读者想回放原话，没有锚点；
2. **易失真**：转写错字被悄悄改顺、整理者的话被当成原话。

外部两个项目把这件事做透了，本馆直接借其**结构**，不借其**内容**：

| 项目 | 借什么 | 不借什么 |
|---|---|---|
| `nihai-tianji-corpus` | 判语条目格式、秒级溯源拼法、保真门禁、勘误闭环 | 4886 条原文（CC BY-NC-SA，只放工作区，不进插件包） |
| `tcm-db` | SQLite 分表 + 关系表 + 审计设施（evidence / quarantine） | 3867 条记录本体 |

## 2. 判语条目格式（命理版 `entries.jsonl`）

一条判语 = 一个 chunk，不再切。机读与人文读两份同体：

```
{"册":"03-patterns", "h2":"七杀朝斗", "h3":"成格条件",
 "quote":"七杀坐命寅申，对宫迁移为紫微天府，此格主武职权威。",
 "src":"BVID", "part":3, "section":10, "t_hms":"00:40:09", "note":""}
```

字段约定：

| 字段 | 含义 | 必填 |
|---|---|---|
| `册` | 命理馆册号或天纪册名（如 `11` / `03-patterns`） | 是 |
| `h2` / `h3` | 二级／三级主题（宫位、星曜、格局名） | 是 |
| `quote` | 倪师原话短引文，**照抄可标〔sic〕，不许改顺** | 是 |
| `src` | 视频源：B 站 `BVxxxx` 或本馆排盘工具快照 `tool://…` | 是 |
| `part` | 分P 序号 | 是（视频源时） |
| `section` | 讲内段落号 | 否 |
| `t_hms` | `时:分:秒`，可拼 `?p=N&t=秒` 一键回放 | 是 |
| `note` | 勘误／流派差异注（原话不动，只在此加） | 否 |

**回放拼法**：`https://www.bilibili.com/video/{BV}?p={part}&t={时*3600+分*60+秒}`

## 3. 保真七道门禁（适配本馆）

从 `nihai-tianji-corpus` 的七道门禁改成本馆口径，每条判语入册前过一遍：

| # | 门禁 | 本馆做法 |
|---|---|---|
| 1 | 空批次防线 | 无 `quote`／无 `src` 的条目不入库 |
| 2 | 秒级去重 | 同 `册+part+t_hms+quote` 只存一条 |
| 3 | 探针覆盖 ≥95% | 每条须有可回放锚点（B 站或工具快照） |
| 4 | 一致率 ≥60% | 双源（OCR × 双 ASR）冲突的，标「待核」不入库 |
| 5 | 术语白名单 | 星曜／宫位／格局名走白名单，错字标〔sic〕 |
| 6 | 出处可回溯 ≥95% | 95% 以上判语须能拼出回放链接 |
| 7 | 逐字命中 ≥90% | 引文须为原话子序列，不得改写 |

> **只删不改铁律**：清洗文本须程序验证为原文子序列；AI 越界改字的一律作废转人工。

## 4. 勘误闭环（原话不动，只加注）

发现倪师口述与古籍／排盘验算不符时，**原话保留，条目加注 `〔勘误：…〕`**：

- 例：`64` §3 结论四——倪师安星南北斗归属与《紫微斗数全书》不合的六颗星，册页正文照录，仅加编者注。
- 例：`nihai-tianji-corpus` 自己记的「文昌化忌在田宅」系排盘笔误，原话保留、加注、同步 docs／数据／检索三处。
- **勘误账本全量公开**：所有改动留痕，可回查"哪天、因什么、改了哪句"。

## 5. 审计设施（借 `tcm-db` 的 SQLite 思路）

命理馆判语库若落地为 SQLite，采用「核心实体 + 关系表 + 审计表」三层：

```
核心实体：  stars(星曜)  palaces(宫位)  patterns(格局)  judgments(判语)  classics(古籍原文)
关系表：    star_palace(星曜↔宫位)  pattern_star(格局↔星曜)  judgment_src(判语↔出处)
审计表：    evidence(字段级来源证据)  ingestion_quarantine(脏数据隔离)  id_redirect(旧ID重定向)
```

- `evidence`：每条判语记"来自哪个源、哪一分哪秒"，可回查；
- `ingestion_quarantine`：双源冲突／无法核对的先隔离，不污染主库；
- `id_redirect`：册页重编号时旧 ID 仍能跳转到新 ID。

## 7. 落地三步（本轮即做）

1. **册页加锚点**：新写的紫微／天纪／经方判语，统一带 `册·h2·h3 @时:分:秒`（有视频源的）。
2. **建 `entries.jsonl` 草案**：把 `11`/`15`/`62`/`63` 里的倪师原话抽成判语条目，放工作区 `.workbuddy/data/nihai/`，不进插件包。
3. **接查询**：`nihai_query.py` 增加 `--库 tianji` 通道，能按册／宫位／星曜／关键词检索判语并拼回放链接。

> 一句话：**排盘借引擎，断语借语料，每一条判语都要能回放到那一秒。**

## 8. 引用块的三种身份（2026-11-02 补，附回查脚本）

册页里用引用块（`> "……"`）写句子，本来是为了"一眼看出这是原话"。但写多了会混进两种别的东西，混进去之后**机器与读者都分不清哪句是资料、哪句是本馆拟的**——这比引错字更麻烦。

### 8.1 三种身份，三种写法

| 身份 | 写法 | 判据 |
|---|---|---|
| **资料原话** | `> "……"`（独占一行，可带 `**` 加粗） | 必须能在语料里逐字找到；省略处用省略号，**不许改字** |
| **话术示例** | `> 〔话术示例〕"……"` | 这是本馆演示"该怎么对客户说"，不是谁的原话 |
| **本馆归纳** | `> 〔本馆归纳〕"……"`，或直接作正文叙述 | 本站自己的总结，属 `66` 的"整理层" |

**为什么不统一成一种**：三种东西的**可信度不一样**。客户追问"这是谁说的"时，原话要能指到人、指到书；话术只能答"这是我们拟的说法"；归纳要标〔本馆归纳〕。混成一种，就等于把本馆的话冒充成倪师的话（`66` §1、`68` §5 的推理隔离）。

### 8.2 自检脚本 `scripts/verify_quotes.py`

```bash
cd skills/xuanjian-kb/scripts
python3 verify_quotes.py ../references <语料目录>          # 只列待查
python3 verify_quotes.py ../references <语料目录> --全      # 逐条列结论
```

它只做一件事：把**独占一行的引用块**拿到语料里逐字找（先把语料与引文都去空白，对付逐行排版的电子本），报出找不到的。

**三条必读**：

1. **待查 ≠ 造假**。常见三种：① 语料是繁体、册页已转简体；② 引文来自别处语料（另一包 jsonl、网上语料）不在给定目录；③ 原文跨了页眉水印，引用时跳过。
2. **但它能抓出"改顺"**。本轮实测就抓到两处：`80` 把原文口误"用身体系"改成了"用神体系"，`27` 把"随时会发生的""它也有很多好的因素"改成更顺的句子。**这类错只有脚本抓得到，人眼看不出来**，因为改完更通顺。
3. **改顺要改回去**，不是保留。原字照录，讹字标〔原文作…〕（§3 门禁四、§4 勘误闭环）。

### 8.3 存量与节奏

- 本轮已给 8 处误用引用块的句子加了〔话术示例〕／〔本馆归纳〕标识（`21`×2、`26`、`27`、`29`、`35`×2、`73`）。
- **新写册页时**：原话才用引用块，拟话术一律加前缀。
- **每轮摄取后**：跑一次 `verify_quotes.py`，待查清单逐条判性质，别整批放过也别整批改回。

> ⚠️ **工具能查的只是一部分。** 早期册页（`01`–`74`）大量用**行内引号**（`他说"……"`）而非引用块，脚本只抓得到两种：独占行的引用块、带「原文／原话／原句」引导语的引文。**行内无引导语的引号，机器分不清是引用还是强调**——那部分只能人工核。
>
> 所以：**"脚本跑过、待查为零"不等于"全库引文都验过"**，只等于"可机器核的那部分验过了"。新册一律用引用块，就是为了让这类核验将来能覆盖得更多。
