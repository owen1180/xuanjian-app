# 一百零四、三平台生态复查与计数口径台账

> 建档 2026-11-07。**这一册不讲课，管「GitHub／WorkBuddy／OpenClaw 三条线的数字怎么算、能不能加、哪些机制能进本馆」**。
> 依据 `OB95`（外部情报先核验）、`OB97`（引一句查一句）、`KB98`（版本与合法取书）、`TR101`（只借机制不搬实现）、`KB103`（上一轮对拍数据核验的同一套方法）。
> **本册是事实台账＋本馆归纳，不是断法册**：不复制任何外部仓库的 README 段落、解读文本、断语表或格局表。

## 一、对象核实（先把名字钉死）

| 平台 | 真实对象 | 公开一手数据源 | 形态 |
|---|---|---|---|
| **GitHub** | 源码托管，不是市场 | `api.github.com/search/repositories`、`/repos/{owner}/{repo}`、`raw.githubusercontent.com` | repo（引擎／skill／评测集／语料） |
| **WorkBuddy** | 客户端＋专家中心 | ① CDN `expert_center.json`（429 专家，`lastUpdated 2026-08-18`）② 本地已安装官方包 ③ `api.skillhub.cn` | 专家 agent／专家团 team／skill |
| **OpenClaw** | 开源自托管 AI agent（MIT），Clawdbot → Moltbot → 2026-01-30 定名；技能注册表 **ClawHub**（`clawhub.ai`） | `/api/v1/skills`（游标分页）、`/api/v1/search`（向量检索）、技能页 `/{owner}/skills/{slug}` | skill bundle／plugin |

**三平台不是互不相交的集合**：`api.skillhub.cn` 的技能里有 `namespace=clawhub_*`——**skillhub 聚合了 ClawHub 的包**。上一轮竞品「命理大师」即 `clawhub_wscats/university-applications`。〔本馆归纳〕**跨平台相加必然重复计数**。

**客户端能力分配不变**：个人源无 `payAssets`／`featured`／`teamTab`／`recoSort`；官方 CDN 清单由运营维护、客户端只读，**公开上架走官方提审，没有自助入口**。

## 二、四层数字，一个都不许相加

| 数字 | 含义 | 用途 |
|---|---|---|
| **429** | WorkBuddy CDN 专家清单条数（官方策展） | 分母，算命理占官方层比例 |
| **8,614** | ClawHub 本次游标抓取 45 页去重数（**下界**，非全站总数） | 分母，算通用注册表长尾比例 |
| **573 / 169** | skillhub／ClawHub **搜索候选池**去重数 | 只作线索清单，不作「已核实技能数」 |
| **5,705+ / 61+** | 站点宣传计数（不同站点、不同时点） | 单列，不进定案级规则 |

**游标不收敛（本轮方法论发现）**：`/api/v1/skills` 按 `by_active_updated` 排序，传 `nextCursor` 可持续翻页且**去重后仍无重复**——45 页 8,614 条、100 页 19,301 条时游标仍未终止，远超站点宣传的「5,705+」。故该接口**不能用于全库穷举**，8,614 只能登记为「本次抓取下界」。要统计术数占比，用 `/api/v1/search` 关键词召回＋精确筛选更可靠。按 `OB95`，宣传计数与实测下界分列，不相加、不互相校正。

## 三、同一包、两套计数（最硬的口径发现）

`wscats/university-applications`「命理大师」：

| 来源 | downloads | installs | 备注 |
|---|---:|---:|---|
| `api.skillhub.cn` | **58,200** | **769** | `namespace=clawhub_wscats`，★104 |
| `clawhub.ai/api/v1/search` | **24,386** | **2** | `metrics.rolling60DayInstalls`，`featured=false` |

同一个包，两处 downloads 差 2.4 倍、installs 差 384 倍。skillhub 573 个候选的 downloads 合计 **802,790**，installs 合计 **6,146**（约 130:1）。**`downloads ≠ installs`，且跨平台同名计数不同源**；把下载量说成「用户数」「市场规模」都是错的（`OB95`／`OB98`）。

## 四、WorkBuddy 三层复查

- **官方 CDN**：429 专家，强特征词命中 3 个——`FortuneConsultant` 运势分析师、`FortuneMaster` 生辰命理大师（**严格命理 2 个 agent**，均为 `12-IndustryConsultant`）、`StudyFortuneCompass` 学运趋势解读师（**边缘**，仅描述含「卦」）。早前用「算」做关键词曾误报 51 个（算法／算账／投研全被扫进来），**关键词宽度决定结论，这一条要写进方法台账**。
- **本地官方包**：`mingli-yanpan` 命理研判专家团 v1.0.1，GPL-3.0-or-later，4 agents＋3 skills，自述「三路并行，各自独立排盘判读，再由总纂对照汇总；严守体系隔离，不互译不加权」。〔本馆归纳〕与本馆 `OB99` 三段式合参、`TR103`／`TR104` 口径只读·派单独立同构；其 quickPrompt「三路结论不一致，请分列各路原话与判据卡片」可对照本馆「分歧全量保留」。
- **skillhub**：25 个中英关键词 × `limit=50` 向量检索（**返回最相似 50 条，不是精确匹配**），二次精确筛选去重得 **573 个候选**；namespace 分布 `clawhub_*` **130**／原生 **443**；分类集中 `life-service` 332、`knowledge-management` 97。**收费字段在 `labels.pricing_type`，不是 `price`**：`paid` 22、`alipay` 41、未标 510，合计 **63 个付费**（11.0%）；另有 `requires_api_key`。抽样 18 条确认为真实术数内容，但存在内容聚合类边界条目，故 573 定位为**候选池**。

## 五、OpenClaw / ClawHub 复查

- **API 口径**：`/api/v1/skills?limit=500` 单次上限约 200 条，需 `nextCursor`（JSON 对象，序列化后 URL 编码）；`?q=` 不生效，**搜索要用 `/api/v1/search?q=`**；详情路径是 `/{owner}/skills/{slug}`，`/api/v1/skills/{owner}/{slug}` 返回 404。本轮首次试探踩过这三个坑。
- **列表强特征命中 21 条 / 8,614（0.24%）**，人工复核约 15 条真术数，其余是 `cn-llm-router`／`prometheus-fire`／`skill-quality-gate` 等被宽词误命中；**搜索端点 23 关键词去重 169 条**，头部 `命理大师` 24,386、`Bazi Pro` 5,646、`AsianSeeker` 3,907、`Awesome Bazi Calculator` 2,916。
- 〔本馆归纳〕ClawHub 以英文／国际社区为主、术数占比低；skillhub 以中文原生为主、密度高得多。**中文命理 skill 的主场在 skillhub。**
- 治理：文档称发布需 GitHub 账号满一周、3 个独立举报自动隐藏、版本历史可审计、技能 zip 可逐文件检查。本轮只核到文档层，**未做恶意包实测**。

### 不借

1. 把 GitHub `total_count` 当项目数。
2. 把 `downloads` 当 `installs`，或跨平台相加同名计数。
3. 把「5,705+／61+」当实测，或与游标下界相加。
4. 把 573／169 说成「已核实的命理技能数」（它们是搜索候选池）。
5. 把 `liki` 的 829 条断语／893 条件组搬成本馆断语库，或把统计说成准确率（`TR100`／`TR106`）。
6. 彩票测算器、投资方向建议、付费「化解」类技能——撞本馆合规红线。
7. GPL-3.0／AGPL／无 LICENSE／PolyForm NC 的实现与 README 文本（`OB95` §4）。
