### 2.1 紫微五层（v1.3–v1.5 分批落地，对应 `15`）

紫微此前只有「排得出盘」，v1.3 起逐层补上判定层。成员读紫微盘时，**这几层直接取工具结果，不要手推**：

| 层 | 内容 | 落点 |
|---|---|---|
| **格局** | 36 条三合派常用格局，每条带 `required / bonus / breaking` 与出处；只给**结构倾向**，不给成品断语 | `src/engines/ziwei-patterns.ts` |
| **十二神煞** | 将前十二神、岁前十二神、博士十二神 | `src/engines/ziwei-shier-shen.ts` |
| **四化（六层）** | 本命（生年干）／大限（宫干）／流年（年干）／流月（五虎遁）／流日（农历日干）／流时（五鼠遁），另加**宫干自化** | `src/engines/ziwei-sihua.ts` |
| **运限** | 大限 12 步（起止虚岁、起年、宫名、宫干、宫干四化）＋ 当前大限定位；未入大限前走**童限**（虚岁 1–4/5 按流年移宫） | `src/engines/ziwei.ts`、`ziwei-yunxian.ts` |

三条必须讲清的口径：

1. **流月／流日／流时锚在「当下这一刻」的农历，不是出生时的农历**。本命、大限、流年三层锚在命主生命周期上，流层锚在当前时刻上——问的是「这个月／今天／这个时辰，四化把哪颗星挑动了」。所以流层每次排盘都随日期变化，属正常。
2. **多层同见才作强断，单见一层只作倾向**。层数越多，该星在本运中的动静越明显。
3. 四化是**变化方向**（禄＝增益缘至，忌＝执滞耗损），不直接等同于吉凶；成格不等于必成，破格也不等于无成。

### 2.3 六爻与梅花：引擎只装卦，断法归 `82`

引擎能出（`36` §2 表）：**本卦、互卦、变卦；世应、六亲、六神**。
引擎不能出：**取用神、旺衰、动变、应期、断语**——这些归 `82` §3–§5，由斗枢做。

| 项 | 引擎 | 人 |
|---|---|---|
| 纳甲、世应、六亲、六神 | ✅ 装卦 | 只核对，不手装 |
| 梅花上下卦、动爻、互变、体用 | ✅（`scripts/meihua.py` 亦可独立跑） | 断法归人 |
| 取用神（问什么取哪一亲） | ❌ | ✅ |
| 旺衰四看、七种易漏形态、应期 | ❌ | ✅ |
| 体用生克断语 | ❌ | ✅ |

> **一句话**：**装机部分交给程序，问事部分留给人**。引擎给出"这一爻是什么"，不给出"这一爻说明什么"。

### 2.6 页面怎么分：按「输入」分，不按术数名分（v1.16.0）

术数名字是给人看的，输入才是给程序看的。故首页不把八门平铺，而按「问什么」分组，
每组一页或数页，各页只吃自己那一种输入：

| 页 | 路由 | 只吃什么 | 出什么 | 明确不算 |
|---|---|---|---|---|
| 导航台 | `/` | 不用输 | 八门入口、资料库条数 | 不排任何盘 |
| 命盘 | `/bazi` | 生辰＋性别＋出生地 | 四柱、大运流年、旺衰用神、紫微十二宫、疾厄、合婚 | 不算日子、不算名字、不起课 |
| 起名 | `/qiming` | 姓＋名＋（可选）生辰 | 方向、门槛、现名五格与可核项 | 不打分、不排名次、不排命盘 |
| 黄道吉日 | `/zeri` | 公历日期＋用事 | 建除黄黑道、三栏、方向、窗口速览 | 不取生辰、不算冲命主 |
| 易占 | `/yi` | 起课时刻 | 梅花（本互变动爻）／六爻（六亲六神世应） | 不取八字、不出断语 |
| 奇门 | `/qimen` | 起局时刻 | 九宫、三奇六仪、八门九星八神、值符值使 | 不判用神落宫吉凶 |
| 六壬 | `/liuren` | 起课时刻 | 月将、四课、三传、天地盘 | 不判课体吉凶 |
| 阳宅 | `/fengshui` | 出生年＋性别（坐向可选） | 命卦、八方吉凶 | 未纳门主灶路，不作验收 |
| 资料库 | `/library` | 不用输 | 按门类统计、取回原文、撤误存 | 不统计吉凶、不做排行榜 |

**判据只有两条**：

1. **输入不同就分**。日只吃日期、名只吃姓与名、课只吃时刻、命只吃生辰——四种输入互不替代，
   合成一页必然要「让某一门将就另一门的输入」，那就会偷偷带上八字。
2. **必须互参就合**。八字与紫微同吃一个生辰，且交叉印证要同屏对照，故合成 `/bazi` 一页；
   拆成两页要输两遍生辰，还会出现「同一时刻两页算出不同四柱」的口子。

**同一事、不同起卦法**（梅花／六爻）合成 `/yi` 一页两入口：它们问的是同一件事，只是起卦与排法不同；
分两页会让人误以为「梅花问这个、六爻问那个」。

**接口与页面同构**：`/api/classic` 按 `kind` 只算那一门（`src/server/classic.ts`），
返回体只有本门数据——独立性写在返回体里，不只是菜单里。例外是八字：深度分析要看整盘，仍走 `paipan()`。

**合参仍不做**：按某人的命挑日、按某人的命断课，本版没有，也没藏在别的页里。
要做须单开一页并写明「以某人生年支为参」（`83` §10、`90` §10）。

> ⚠ **订正层文本须与档案现行定案逐字对齐（R-032）**：档案升级定案时，订正层登记表（`src/analysis/dingzheng.ts`）、回归基准「订正层」快照、册页引文三处同刷。订正层按设计「不判漂移、只提示」，不会随引擎计算层自动同步，最易滞后；历史说法只在差异说明里以「已作废」存档，不作现行结论。

订正层的做法是**两边都不动，只并排呈现**：

| 纪律 | 内容 |
|---|---|
| 只登记已成档的 | 只收**已写成档案、有规则编号**的订正（`R-xx`），不登记临时判断 |
| 分数不手填 | 打分法分数由引擎算，缺时柱一律 `null`（`41` §7：缺时柱不打分） |
| 冲突两边都说 | 与工具口径冲突时**并排写出**，不许静默顶替，也不许拿引擎去压人工定案 |

> 这正是本馆「引擎初判 vs 人工定案分层」那条边界的代码化：引擎算它的，档案定它的，
> 冲突进「待复核」由人裁定。见 `src/analysis/dingzheng.ts`。

**校验锚点（双锚点，均不可破坏）**：

- **主锚点（`41` §7 回填案例）**：`丁酉 己酉 丙午 辛卯` → `40.5 + 70 = 110.5 → 中和`。验的是「年干比劫折让一成」「财与食伤参与天干反应」两条。
- **副锚点（`01` §6 原例）**：`丁巳日、月干癸、时干乙、年干丁、地支丑亥巳` → 按 `01` §3 规则重算 `43.2 + 138 = 181.2 → 偏旺`。

> ⚠ **口径修正（重要，引用前必读）**：`01` §6 的算例**漏计了年干丁（比劫）**，写的是 175.8。
> 但 `01` §3 明立「年干是比劫才计入；月干非比劫则折让一成」，`41` §4.2 复述同一条，
> `41` §7 的 110.5 也只有把年干比劫计入才对得上。
> 按 `41` §5.1「必须拿例题反测规则，不能只读结论句」，工具**采规则、例题按规则重算**，
> 并把这条分歧写进 `scoring.calibration.conflicts`。**对外引用不要再报 175.8。**

改动打分逻辑若破坏任一锚点，回归测试即红（`tests/scoring.test.ts`、`tests/expert.test.ts`）。

### 3.3 干支总纲（v1.7，对应 `49`）：地支不随意生克

`49` 解决的是最容易被想当然的一类错误——把天干那套「相邻就能生克」原样搬到地支上。
本门规矩：**天干主动，地支主静**，地支不在七种关系里就当作不发生反应。

| 项 | 落点 | 说明 |
|---|---|---|
| 柱内五类 | `analyzeZhuXing` | 比和一气／支生干／干生支／盖头／截脚 → 天干实透还是虚透。只作说明，**不动打分**（打分另有柱型基准，见 `01` §2、R-34） |
| 地支七种关系 | `zhiReact` | 六冲、六合（分生合克合）、三会、三合、半三合、拱合、相刑、相害；**不在其内即返回「不发生反应」**——寅酉看似金克木、巳辰看似火生土，都不发生关系 |
| 财库 | `caiKu` | 丙丁→丑、庚辛→未、壬癸→戌、戊己→辰；甲乙木无库而辰戌丑未皆为其财。自坐四柱：丁丑、壬戌、戊辰、辛未 |

两条纪律写在代码里：**财库断语只说「攒得住／攒不住」，不许说富不富**（`49` §5.2 明指「自坐财库无人不富」不严谨）；
**日元五行不跨盘论生克**、生肖合冲不等于婚姻好坏——这两条属对外话术，不进引擎。

**判定次序有讲究**：一支常同属多个集合（午未既在巳午未三会方内、又是六合生合），
先判两支直接关系（六冲、六合），再判会合之势；三会三合要三字齐才算成局，只给两支时记作「势」。

### 3.6 旺衰取哪个层次：两种口径并存，且必须公开分歧

工具同时算两套旺衰，**定论取占比口径**，但把分歧原样写进结论：

- **打分法（`01`）**：日元绝对分。只计同类根气，不计地支印星、也不计「土多生金」之势，对**印重／比劫重**之盘系统性偏低。
- **透藏加权占比**：自党 : 异党。对上述盘更贴近实际。

典型例子：`乙丑 庚辰 庚辰 辛巳`。打分法判偏弱，占比 62.7% 实为身旺；若照打分法层次取用神，会得「扶抑用金、忌火」，与定案「用木、忌金」正好相反。

所以工具的行为是：`level` 取占比口径，`scoring.level` 照常输出，二者不一致时在结论里写一段「口径分歧（须讲明）」，**不许悄悄盖掉**。成员引用时也要连带说明，不能只报一个层次。

**已知边界**：本工具无手面相照片输入，合参只做「命局 × 阳宅」两盘；相法槽位保留，不拿两样推第三样（`14` §6）。

| 事业 | `analyzeShiYe` | 用神五行对应的行业大类、动静倾向（用神中动星多还是静星多）、用神落点、级别倾向 | **具体职业**；降级与年代修正由人判（`53` §7） |

### 3.11 流年四步与术语（对应 `55`）

流年不再只报「地支冲了什么」，而是按 `55` §3 的四步走：

| 一 | 流年柱型：天干实透还是虚透 | 干支五行关系定：同／被生＝实透；生／克＝虚透（盖头）；被克＝虚透受损（截脚） |
| 二 | 天干算不算进吉凶 | **只有两种例外**：天干在本柱实透；或天干克原局天干用神。其余一律「以地支论」 |
| 三 | 流年地支与原局四支的反应 | 走 `49` 的 `zhiReact`——**同一把尺子**，不在七种关系内即「不发生反应」 |
| 四 | 十神方向与吉凶 | 流年十神是本命哪个十神的同类，取该十神的用忌方向 |

十九个术语（`55` §2）做命中表：**只判「成立／不成立」，不附吉凶**。术语是描述盘面在说什么，不是判词。

### 3.12 阳宅名位与内外卦（对应 `10` §4＋`18`）

这一层是唯一**不吃生辰**的分析模块：输入是「谁 + 住哪个方位」。

规则不是自拟的，是拿 `10` §4 全表 37 条反测出来的——**上卦＝人（八卦配家人），下卦＝位（八卦配方位）**，无一例外：

| 例 | 得卦 |
|---|---|
| 父居西北 | 上乾下乾 = 乾为天 |
| 母居父位（西北） | 上坤下乾 = 地天泰 |
| 次子居正东 | 上坎下震 = 水雷屯 |

- **住宅**：人＝外卦、宫位＝内卦；**办公室**：门朝向＝外卦、办公室方位＝内卦（`18` §5）。
- **成格三查**：人在不在场、婚否、是否同住——用结构化字段判，不靠正则猜文档原话。
- **时效卦**：大壮三个月、谦与遁 65 岁、咸单年（`10` §4.2）。

**断语一律不出**：讲义原表的「死先生」「长子夭折」「必凶」须按 `10` §6 转成风险语言，
措辞归成员，受 `57` 红线闸门锁死。工具只给「名位错位」这个结构事实。

> 已知两处文档冲突，工具不代改、两说并存并标注：`10` §4.2「山风蛊｜少男居西南」与卦名不符
> （艮上巽下应居东南，「三子居西南」是山地剥）；`18` §5.2 办公室原例「坤上乾下＝地天泰」
> 把内卦置于上位，与外卦在上的通例相反。两处均已在册页加编者注待回课核。

### 3.14 校时与解冲（对应 `58`）

两件事都来自第二十三课，都是「拿可验证的东西把不确定钉住」。

**校时**（`src/analysis/xiaoshi.ts`）——时辰不准时唯一的正路：

| 步 | 做什么 |
|---|---|
| 一 | 列候选时辰（通常 2–3 个，边界时辰优先） |
| 二 | 各排一盘、各取用神（走 `01`／`02` 同一套，不换口径） |
| 三 | 拿**最近十年、对方记得住、且五行有力**的流年反推（用土问 2009 己丑、用火问 2014 甲午） |
| 四 | 命中率最高的为「较贴」；**并列即报分不出，不许硬选** |

工具输出每候选的四柱、用忌、逐年顺逆与命中率，另给 `best`／`tie`。
「找不准用神就不要继续往下算」是 23 课原话，也写进了结果的边界句。

**解冲**（`src/analysis/jiechong.ts`）——冲能不能解开，看五行往哪边走：

| 岁运来字 | 与冲方的关系 | 结果 |
|---|---|---|
| 六合冲方 | 绊住冲方 | **解**（六合最有力） |
| 克冲方 | 冲方受制 | **解** |
| 冲方生它／克它 | 冲方出力耗势 | **部分解**（刑、害、半三合多落这一档） |
| 与冲方同气、或生冲方 | 冲方得势 | **加剧** |
| 不在七种关系内 | — | **无影响** |

原例（婚姻宫酉、卯冲）五项逐条对拍：戌解、未部分解、辰缓解、亥加剧、子加剧——
**注意辰既害卯又合酉，老师判「适当缓解」而非全解，所以「合住被冲方」只在无其他作用时才定论。**

### 3.15 四柱部位与健康取象（对应 `59`）

23 课要求背下来的坐标：**年柱头、月柱胸腹、日柱腹下、时柱腿脚**；天干主外、地支主内。
叠上五行三档，就是工具给的那句「宜留意哪一块、宜查什么方向」。

| 档 | 判据 | 出口 |
|---|---|---|
| 缺 | 原局不见 | 该行所主系统偏弱，要看大运补不补得进来 |
| 弱而被制 | 克它者 ≥3 处且不少于自身三倍（**本馆定的量尺，可调**） | 比「缺」更明显 |
| 太旺 | 四处及以上 | 旺极反伤其所生所克 |

**行数按八字算**（天干＋地支本气），不用 `wuyun.ts` 的四支计数——那个为中运而设，
拿来判缺会把天干的金木漏掉，报出「庚辛在干却说金缺」的假警。

十四条细目（「木被金伤，筋骨腰肋疼痛」一类）**不进引擎**：症状与病名混合，脱离问诊必错。

## 5. 用这套工具时的纪律

1. **引擎是初判，不是定案**。工具出的旺衰与用神带「引擎初判」标记；库中若有人工定案，一律保留人工结论，冲突自动记「待复核」，由人裁定。
2. **先核盘再引用**。用户自报四柱与引擎不一致时，先查真太阳时、夏令时、闰月、晚子时四项口径，再谈结论。
3. **分数不跨体系比较**。本体系 175.8 分与他人软件的「身强」不通用（`01` §8），不许混着说。
4. **层次不定不报「必发」**。工具给出 `断语封顶`，那就是这盘话能说到的高度；越线即 `39` §2 所说的越界。工具的 `allowStatement()` 会直接把「必发／必富／必贵／必离婚」这类句式判为越界。
5. **点数不到不说应期**。象法要看「大运先动 + 流年同指」两点以上；工具只给 1 点的，只能当提示，不许说「这一年会××」。
6. **寿元星一律转译**。工具输出已把禄神／寿元星被冲写成「健康关口、宜有人陪伴、宜先做检查」；**不得改回「死／大限／必凶」**（`37` §7）。
7. **合参不硬凑**。没有照片就只做两盘，明说「少了相法这一层，力度降一档」；不许从八字反推长相。
8. **分寸照旧**。工具再完整，结尾仍按本库 `24`–`28` 兜：不诊断、不代做投资法律决策、不承诺金额与日期。
9. **归档按八字查重**。同八字并入既有命造，不重复建档；分析记录只追加，不覆盖。
10. **合化只在取用层生效，打分时不计**（`48` §6）。断事时判了「戊癸化火」，转头算分不许把五合加成算进去；反过来，算分阶段也不要拿五合去解释分数。两步混用，分数就虚高。
11. **紫微的格局与四化取工具值，成员不重推**。36 条格局只给结构倾向，成员要做的是把它落到具体人事与条件上；`15` §1 的取象仍归人判，工具不代取。
12. **年过六十自动收应期**。闸门给出 `timingAllowed = false` 时，流年段只讲气势方向，不落「哪一年会怎样」——这是本门自己划的边界，不是保守。

**结论**：工具负责「把可确定的部分做到零幻觉」，成员负责「把不确定的部分讲清楚」。两边口径必须同源——都以本库 `01`／`02`／`14`／`15`／`37`／`38`／`39`／`48`／`53`／`54`／`57` 为准。

### 6.1 自动归档闭环（v1.1 起，档案卡片同步更新）

排盘即建档，不靠人记得去做：

1. **八字是唯一键**——同八字自动并入既有命造，同一命主的多次测算追加成流水，不重复建档（与 `xuanjian-archive` 同规则）。
2. **档案卡片同步更新**——新结论写回卡片，旧结论按效力分级保留，人工定案字段一律不覆盖。
3. **自动学习带闸门**——引擎初判与库中人工定案冲突时，只记「待复核」由人裁定，**不静默覆盖**（`src/archive/learn.ts` 的 `keepOrFlag`）。
4. **单一数据源**——桌面端、CLI、主库三处写同一份 `registry.json`，不出现两套结论。

> 成员侧的动作只有一个：看到「待复核」就去裁定。别绕过闸门直接改库里的结论字段。

## 7. 知识库变更如何自动流到工具

本库还在长。工具侧装了同步闸门，解决「本库更新了、软件还是老口径」：

| 动作 | 命令 | 作用 |
|---|---|---|
| 查变更 | `npm run kb:check` | 逐文件 sha256 比对基线，列出新增／修改／删除 |
| 机器读 | `node scripts/kb-sync.mjs --json`<br>（或 `npm run --silent kb:json`） | stdout 只出 JSON，供自动化分支判断。**别用不带 `--silent` 的 `npm run`**，npm 横幅会混进 stdout 把 JSON 弄脏 |
| 推基线 | `npm run kb:accept` | 处置完把当前状态接受为新基线 |
| 当闸门 | `npm run kb:gate` | 有活没干时退出码 3，可挂 CI |

判据写在 `.kb-sync/coverage.json`，每份文档标一格状态：

| 状态 | 含义 | 被改动时 |
|---|---|---|
| `implemented` | 已编码进引擎 | 视为**规则可能变了**，先拿文档例题反测，再改代码 |
| `partial` | 编码了一部分 | 同上，且检查剩下那部分是否该补 |
| `pending` | 能编码但还没做 | 排进待补队列 |
| `manual` | 需照片／现场／研判 | 只提示，不触发编码 |

新文档未登记 → 先判「可编码／需人判」，写进覆盖表再决定。脚本会给一个 `hint`（按「算子·权重·判定表」与「照片·现场·体感」两类词的相对密度估），但**只作参考，不作结论**。

**处置铁律**：

1. 锚点测试红了，先怀疑自己，别改锚点。
2. 真与文档冲突，就把冲突写进结果的 `calibration.conflicts` 并同时保留两条锚点——**不许悄悄改数**。
3. 改完跑 `npm run test` 与 `npm run typecheck`，再 `--accept` 推基线。
4. 覆盖表里写清「为什么不能编码」，别把没做的事说成做了。

这样本库每加一份能编码的文档，工具下一轮就跟上；不能编码的，明写在表里留给人。

## 8. 反向：工具改了如何回到本册

上面第 7 节管的是「本库 → 工具」。反过来也有一个方向，否则成员会拿着旧口径对客户讲：

| 动作 | 命令 | 作用 |
|---|---|---|
| 一致性闸门 | `npm run sync:gate` | 十项校验：工具版本 ↔ 本册声明版本、成员 md 版本、专家包版本已登记、覆盖表模块存在、专家包技能登记、成员是否知道工具、归档同源、**README 声明的工具版本**、**README 册页数与本册页表是否覆盖全部册页**、**本册模块表是否覆盖覆盖表里的每个已实现模块**。任一项不一致即非零退出 |

> 后三项是拿教训换来的：v1.9 之后 README 一直写「当前 1.5.0」「48 份 references」，
> 册页表停在 48，`53`–`56` 四组能力进了引擎却没人知道——**闸门只查成员 md，不查 README，就漏这一整类**。
> 现在的做法是：README 的版本号、册页数、册页表都进闸门；本册模块表也要覆盖覆盖表里的每个 `implemented`／`partial`。

工具每上一个版本，必做四件事，缺一件就算没完成：

1. 版本写进 `package.json`，**并同步修改本册 §1 的版本号**；
2. 新增／改判的模块写进 `.kb-sync/coverage.json`（别把没做的事说成做了）；
3. 本册模块表补一行、给一段口径说明；专家包 `README.md` 的版本号与册页表同步（新建册页就要加行、改总数）；
4. 跑 `npm run sync:gate` 通过，再打包。

> 这条是拿教训换来的：v1.3–v1.5 一口气补了紫微五层，本册却一直停在 1.4.0 的口径，
> 专家团那边完全不知道工具已经能算格局与六层四化。两侧各说一套，是本馆最不该出现的错。
