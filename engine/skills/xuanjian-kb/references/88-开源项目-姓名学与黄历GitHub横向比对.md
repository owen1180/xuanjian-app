## 2. 五个结论（先行）

1. **黄历侧不是空白，是做满了，而且不止一家。** `cnlunar` 以《钦定协纪辨方书》为核心，宜忌逐条有依据、有宜忌等第表；`6tail` 全家桶（六种语言、MIT、无依赖）把值宿／胎神／吉神方位／太岁两派都做了。**本馆"不出"的那几栏，别人早就算得出来。**
2. **所以上一轮 `85` 的三个"不出"理由里，有两个不成立**（§5）。真相是：**能算，但选择不出**——因为出了就变成替客户看黄历办事。
3. **姓名学侧：算法满地，断法全无。** 所有涉及"这名字好不好"的，都是打分、吉凶表、数理评分；**没有一个项目能给出"为什么好"**。
4. **唯一的例外偏偏和本馆同结论。** `观象知时·宝宝起名` 明写不打分、不用五格、生肖不进主判据、不对未来断言——与本馆 `84` 各自独立走到同一处（§7）。
5. **数据侧补上一个真缺口**：康熙字典笔划对照表（63696 字，MIT）。但它**按字形给笔画**，简体查表会把三才整个算错（§6.2）。

### 3.1 一条值得学的工程决定

`cnlunar` 作者把节气数据从"寿星通式 `[Y*D+C]-L`"换成**香港天文台实测数据**，理由一句话：**"节气准，农历日期才能准"**。

这与本馆 `74` §11.1 定的历法缺口（节气换年、晚子时、闰月、节气取整四项口径写死）是同一件事。我们的 `sxtwl` 走天文算法，与实测差在分钟级；**危险只出现在交节那一刻附近的日子**——所以对拍时若见月柱不同，**先查是不是交节当天，再怀疑算法**。

## 4. 对拍结果：61 日 × 6 项

拿 `huangli.py` 与 `cnlunar` 逐日对比。第一个窗口是 2026-11-01 起 61 天（六项）：

| 纳音 | 61 / 61 | 6（**泉中水**／井泉水、**沙中金**／砂中金、**沙中土**／砂中土） | 0 |

### 4.1 第二个窗口：2025 全年（含闰六月）

只有两个月不够。再拿 2025 全年（365 天，农历**闰六月**）按五项逐日比：

| 项 | 一致 | 字面不一致 |
|---|---|---|
| 日支 | 365 / 365 | 0 |
| 建除十二神 | 365 / 365 | 0 |
| **值宿** | **365 / 365** | 0 |
| 农历日 | 365 / 365 | 0 |
| 黄黑道 | 365 / 365 | 31（全是**金匮**／金贵） |
| **合计** | **1825 / 1825** | 31（全是异文） |

**两个窗口合计 2191 格，实质差异 0，字面差异 43 处（金匮／金贵 37、纳音 6）。** 值宿在两窗口共 426 天里**一天不差**——这已经不是"差不多"，是可以拿出去对拍的精度。

**12 处不一致全是"同一件东西的两个名字"**：金匮／金贵、泉中水／井泉水、沙中金／砂中金。这不是错，是**版本异文**——按 `81` §5 的规矩：**异文并列，不裁断**。本馆表取通行本的一种写法，遇到客户拿别的通书来对，**照实说"写法不同，指的是同一宿／同一音"**，不许说人家错。

## 5. 收回上一轮的一句话：值宿不是"锚点各本不一"

`85` 上一版写的是：

> 二十八宿值日吉凶｜✘｜锚点各本不一（同一日不同通书可差一宿）

**这句没有实证，本轮收回。** 实测三条：

1. **`6tail` 的值宿是查表**：`LunarUtil.XIU` 共 **84 格**（12 支 × 7 曜），`getXiu()` 取 `日支 + 星期几`。
2. **这张表与"连续轮值"完全自洽**：84 格逐格验"次日是否进一宿"，**零矛盾**。也就是说它等价于「28 日一循环 + 一个固定锚点」。
3. **两家的值宿相同**：2026-11-02，`6tail` 给**毕**，`cnlunar` 给**毕月乌**，本馆按 28 日循环（锚在该日）连比 61 日**全合**。

结论修正为：

| 旧说法 | 新说法 |
|---|---|
| 锚点各本不一，算不准 | **锚点可复算、两家一致**；本馆按 2026-11-02＝毕 为锚，28 日循环 |
| （隐含：我们不会算） | **会算，且已算准**。不出，是**选择**：① 倪师讲二十八宿只讲罗盘配宿，不讲值日吉凶（`85` §0 第 8 条）；② 值宿一旦出口，客户下一句必是"这宿好不好"，那就成了替人看黄历办事 |

所以 `huangli.py` 的处理是：**默认不印**；`--xiu` 只印**宿名**，且固定附一句"吉凶不出，罗盘配宿见 `17`／`20`"。**吉凶表（`XIU_LUCK`）我们一个字段都不取。**

## 6. 姓名学侧：算法满地，断法全无

### 6.1 三类项目，没有一类能回答"为什么好"

| 类 | 代表 | 做什么 | 缺什么 |
|---|---|---|---|
| **打分器** | `peiss/chinese-name-score`（312★，**无许可**，抓 httpcn 数据）、`cnk3x/bys`（Apache-2，八一数理＋康熙笔画）、`rorojiao/namegenius` 等数十个 | 五格／三才／81 数理打分 | **没有判据**：分数从哪来、为什么这个数好，全无出处 |
| **生成器** | `yyz945947732/cnname`、`qiming8/qiming`、各类"AI 一键起名" | 按五行／诗经楚辞抽字 | 抽完给不出"为什么是它" |
| **方法论** | `left-uestc/chinese-naming-guide`（MIT）、`onebluecloud/guanxiang-qiming`（MIT） | 流程化：期许 → 典籍 → 五行 → 多维对比 | 前者仍以五行为主轴；后者**明确拒绝打分** |

### 6.1.1 打分产业的自供

`peiss/chinese-name-score` 的 README 里，作者自己写着：

> 「按八字和五格做名字测试，**不一定真的就是准**，不过它也是中国几千年的文化传承，宁可信其有不可信其无，只要测试出来分数不太低就行了。」

**做这套打分程序的人，自己都留了这条退路。** 这句话比我们讲十句都管用——客户拿 APP 的 92 分来问，把这段念给他听即可（`84` §4.3）。

### 6.2 补上的真缺口：康熙字典笔划对照表

| 项 | 内容 |
|---|---|
| 项目 | `breezyreeds/kangxi-strokecount`（73★，**MIT**，作者 Kawai Lo） |
| 数据 | 康熙字典（正典＋补遗）中 Unicode 11 编码的全部汉字，**63696 字**，CSV 四列：`U+XXXX, 十进制, 字, 康熙笔画` |
| 算法口径 | **按康熙部首笔画算，不按手写笔顺算**。README 举的例：**「華」手写 12 划，康熙归「艸」部（6 划）＋部外 8 划＝14 划** |
| 我们怎么用 | `qiming.py --kangxi 路径`：自动查笔画、与手输对照、缺字报"不猜" |

**但有一个坑，必须写死**：这张表**按字形查**。同一个字，简体与繁体各有一行——

| 名字 | 查表笔画 | 五格 | 三才 |
|---|---|---|---|
| 诸葛亮（简体字形） | 诸15 葛15 亮9 | 天 16／人 30／地 24 | **土水火** |
| 諸葛亮（正体字形） | 諸16 葛15 亮9 | 天 17／人 31／地 24 | **金木火** |

**同一个人的同一个名字，换个字形，三才配置整个变了。** 这一条本身就是五格最硬的反证：若三才真能定吉凶，那么"他该用简体还是繁体"就成了命运开关——可现实里没人这么算过命。**所以五格不取（`84` §4），这里只是把它的算术做准，好在客户面前算得清。**

## 7. 一个同构印证：`观象知时·宝宝起名`

`onebluecloud/guanxiang-qiming`（MIT）是一份 AI 取名技能，与本馆 `84` **互不相识，结论相同**：

| 它的规矩 | 本馆对应 |
|---|---|
| **不打分**——"98 分好名"无判据来源，**打分即编造** | `84` §4：能算不能断 |
| **不用五格剖象／81 数理**——近代日本传入，学理无据 | `84` §1.2、§4 |
| **生肖宜忌不进主判据**——民俗各派互斥，问起才介绍并标争议 | `84` §5.1 |
| **不对孩子的未来做任何断言** | `84` §8 第 2、3 条 |
| 出处三件套：原句＋篇目＋语境判断，查无即写"现代组合"，**不硬挂假典** | `84` §2.3「有来历」；`81` §5 引用规程 |

**它有三件做得比本馆细，本轮借进来**（MIT，注明来源）：

1. **谐音穷举七步**（`84` §3 已改写）：连读拼音串 → 逐音节同音替换 → 相邻组合联想 → 近音扫描（抹调、前后鼻音、平翘、n/l）→ 外号推演 → 拼音书写观感（护照／邮箱形态）→ 方言抽查。**跑不完不进推荐区。**
2. **重名黑名单**：取 2020／2021 全国姓名报告的前十构成字（34 字）直接禁入推荐区，**数据带来源**。
3. **规范字核查**：对《通用规范汉字表》定级，表外字杀——这一条与 `84` §3「录入」是同一条，但它有字表可查，我们只有经验。

## 10. 一句话结论

**黄历这一门，开源世界已经把"算"做完了——所以本馆的价值只剩"不替人算那一栏"。** 姓名学这一门，开源世界把"分"做满了——所以本馆的价值只剩"不给分"。

> 两句话合成一句：**能算的都算准，能不给的都不给。** 前者靠这轮的对拍（366 格零实质差异），后者靠倪师那 9 条原话（`84` §0）。
