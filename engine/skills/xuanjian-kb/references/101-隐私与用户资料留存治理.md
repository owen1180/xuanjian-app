# 一百零一、隐私与用户资料留存治理

> 本册规定玄鉴在**收集什么、存什么、存多久、谁能看、怎么删**上的统一标准。
> 上游：`KB99` 红线 6（不使用现实信息）、`KB100` §四（生物识别）、`23` §9（看图隐私）。
> 本册把这三条从「原则」落成「**可执行的操作规范**」。

---

## 一、数据分类与留存策略

### 一级：敏感身份数据（可留存，需显式授权）

| 字段 | 用途 | 留存规则 |
|---|---|---|
| 出生年月日时 | 排盘 | 可留存于本地档案；用户可随时删除 |
| 出生地／城市 | 真太阳时校正 | 同上；**与出生时间一并视为一组**，缺一则真太阳时结论须标误差 |
| 性别 | 紫微／大运顺逆 | 同上 |
| 姓名 | 取名分析 | 同上；**仅在用户主动要求起名时收集** |
| 六亲出生资料 | 合婚、亲子合盘 | **仅在确实需要合盘时收集**；家庭成员资料单独授权 |

### 二级：生物识别数据（**原则不落盘**）

| 字段 | 规则 |
|---|---|
| 手掌照片 | 不落盘、不进档案，当次会话用完即弃 |
| 面部照片 | 同上 |
| 户型实景照／罗盘照片 | 同上；照片中的门牌、单位名称、地标一律当作没看到 |
| 墓穴／阴宅实景照 | 同上；涉及他人墓地时先确认授权 |

> **技术依据**：掌纹属不可撤销的生物识别信息；人脸属高敏感生物识别数据，泄露后可能被用于身份识别、跟踪或深度伪造，且**没有冷静期**。因此玄鉴对这两类数据采取「**默认不落盘**」而非「默认不收集」——用户可以在当次会话中提供，但系统不持久化。

### 三级：交互记录（可留存，须可查可删）

| 字段 | 说明 |
|---|---|
| 交互主题记录 | 用于追踪用户偏好，**默认关闭**，由用户主动开启 |
| 推送任务日志 | 仅在用户开启每日推送后产生 |

### 四级：档案元数据

| 字段 | 说明 |
|---|---|
| 档案 ID | 随机生成，与真实身份无关联 |
| 建档时间 / 最后更新时间 | 用于留存期计算 |
| 软删除标记 | 默认软删除（可恢复），物理删除需显式操作 |

## 二、最小化原则（收集前的必答三问）

**在收集任何字段之前，先问自己三句话：**

```
① 我现在这个解读，真的需要这个字段吗？
   → 不需要 → 不收集

② 这个解读做完之后，这个字段还有用吗？
   → 没用了 → 收集了也要在本次会话后清除

③ 用户知道我在存这个字段、并且能自己删掉吗？
   → 不知道 / 删不掉 → 不收
```

### 落地示例

| 场景 | 应当收集 | 不应收集 |
|---|---|---|
| 用户只问「今日运势」 | 出生日期 | 姓名、出生地、六亲资料 |
| 用户做合盘 | 双方出生年月日时 | 双方完整住址、单位名称、身份证信息 |
| 用户给照片看手相 | 当次会话中的图片 | 把图片写进档案 |
| 用户问起名 | 姓氏、性别、期望 | 身份证号、真实户籍信息 |

**原则**：**不做该体系解读时，完全不需要填写对应字段。** 这条必须写进对用户的说明里。

## 三、留存期与删除

### 3.1 默认留存规则

- 一级数据：**保存到用户主动删除为止**，无自动过期
- 二级数据（生物识别）：**不落盘**，无留存
- 三级数据（交互记录／推送日志）：随对应功能关闭而停产生；用户关闭推送后，日志不再增长

### 3.2 删除的三种方式

| 方式 | 行为 | 适用 |
|---|---|---|
| **软删除**（默认） | 标记删除，**30 天内可手动恢复** | 误删兜底 |
| **物理删除** | 加 `--purge` 参数，不可恢复 | 用户明确要求彻底清除 |
| **单字段编辑** | 直接改写指定字段，其他字段不动 | 只更新某一项 |

### 3.3 档案管理的四个标准动作

```
查看    show <userId>        默认脱敏输出
列出    list                 只列档案 ID 与时间戳，不出内容
编辑    save <userId> <字段> <值>
删除    delete <userId> [--purge]
```

**脱敏默认**：查看档案时，出生年月日时、家庭成员信息默认部分遮蔽。需完整字段时加 `--full`，且**不得在共享终端、CI 日志、cron 邮件环境中执行**——这些位置会留痕。

### 3.4 第三方录入的额外确认

**若帮他人记录资料**（运营、助理、家人代填），必须在录入前**向被记录者本人取得明确同意**，并告知：

- 将记录哪些字段
- 存在哪里
- 保留多久
- 如何删除

未取得本人同意，**不录**。

## 四、零外呼原则

**玄鉴全部脚本只做本地计算，不得有任何出站网络请求。**

具体禁止：fetch、axios、http/https.request、curl、wget、XMLHttpRequest（脚本侧）、任何形式的 socket 直连。

**唯一允许的例外**（须同时满足全部条件）：

| 条件 | 要求 |
|---|---|
| 触发方式 | 用户在界面上**主动点击**某个可选按钮 |
| 凭证 | 用户**自行填写**的 API key，运行时输入，只存于浏览器 localStorage |
| 发送内容 | **只有**卦象与用户输入的问题文本 |
| 不发送 | 档案数据、环境变量、文件路径、任何本机标识 |
| 端点限制 | HTTPS only，不自动信任 IP 与 localhost |
| 密钥建议 | 提示用户使用**限定额度、限定范围**的独立密钥，不要复用主账号密钥 |

> 这条设计是玄鉴的**信任基线**：用户凭什么把生辰八字交给一个工具？凭的就是「它只在本机算、什么都不往外传」这句话可被验证。

## 五、隐私声明的呈现要求

**凡涉及用户提交个人资料的场景（档案创建、照片提交、合盘录入），首次必须出现以下四项说明：**

```
1. 存什么      —— 列出本次将记录的字段清单
2. 存在哪      —— 明确说明是本机本地存储，不上传
3. 留多久      —— 保存到你主动删除为止
4. 怎么删      —— 给出具体的删除指令，且说明可在任意时候执行
```

**呈现位置**：技能说明正文中可查到，且在首次交互时按需提示。

## 六、禁采集清单（明确不做）

以下信息**任何场景都不采集、不接受、不转述**：

| 类别 | 具体 |
|---|---|
| 法定证件 | 身份证号、护照号、社保号、银行卡号 |
| 精确住址 | 门牌号、单元房号（可用到小区／区级即可） |
| 未成年人全名 | 涉及未成年人时只记小名或代称 |
| 第三方隐私 | 他人的姓名、生辰、面部、住址（除非对方本人知情同意） |
| 敏感健康细节 | 未获明确同意不记录具体病历、检查报告 |
| 账号凭证 | 各类平台密码、验证码、密钥（除用户自填的受限 LLM key） |

## 七、隐私与命理特殊性：两个额外的伦理点

### 7.1 命盘是「不可更换的身份标识」

姓名可改，出生年月日时不可改。一份命盘档案的**可识别性远高于普通资料**——它能反推出性别、年龄、大致地域，部分盘面组合还能反推家族信息。

**因此**：档案 ID 必须与真实身份**无任何关联**；档案不得以用户真实姓名命名；导出或转交时只给档案 ID。

### 7.2 断语档案的额外约束

玄鉴的案例档案（`40` §4 采集案例）额外受一条约束：

> **涉及第三人隐私、家庭隐秘、未证实的指控，一律不写进档案、不在对外文本里出现。**

这条与 `40` §5「不留把柄」一致，落到工程上：**案例采集时只记录盘面与可验证的反馈，不记录当事人身份，不记录第三方信息。**

## 九、一句话总结

**用户把生辰交给你，是因为他相信你不会拿它做别的。隐私治理不是合规负担，是这份信任的技术底座。**
