# 一百一十、基线与裁决：把「学了多少」变成量得出的数

> 立此册的由来：2026-11-05 第十六轮做完学习引擎后，`study.py 状态` 报出两行字——
> 「掌握：平均掌握 0.62（已测 **1** 册）」「待裁候选：NEW 179」。
> 一行是**样本太薄**，一行是**提案没人裁**。两个数看着像进度，其实都是空账。

## 1. 出题器偏科：一个术语表挡住了五类册页

### 1.1 症状

`baseline.py 覆盖` 第一次跑出来：可测 67／勉强 13／不测 **17**。
不测的十七册里，手相、风水、经方、望诊、方剂全在——而十七册的诊断理由
整齐得可疑，全是同一句「有长句但缺判据单位与术语」。

### 1.2 病因

`mastery.py` 的术语表（`distill.术语`）只覆盖**四柱与紫微**两条线。
「纳气」「内气口」「立极点」不是术语表里的词，「三纹」「丘位」也不是。
于是这些册页的句子被判定为「既无术语又无数值」→ 直接跳过 → 出题量为零。

**这不是册页没内容，是词表偏科。** 诊断那一句「缺判据单位与术语」是错的，
准确说法是「本馆的词表不认识这个领域」。

### 1.3 治法：册内自适应术语

从**本册**抽候选术语：加粗词 `**X**` 与表格首列，长度 2–8 字、纯中文，
再用「本册出现 ≥2 次」做频率闸——一次性出现的加粗多是强调用语，
反复出现的才是概念。

结果：**可测 67 → 90，不测 17 → 0**。

### 1.4 代价：栏目名混进来了

自适应一开，`主事`、`注意`、`用法`、`来源`、`仍守` 这类**表格栏目名**开始当答案。
题面挖掉它，读的人根本答不出——它是个标签，不是概念。

试过三道闸，记下取舍：

| 闸 | 做法 | 结果 |
|---|---|---|
| 栏目闸 | 首列反复出现（≥3）的剔除 | 有效，但小表格里栏目名首列只出现 1–2 次，漏网 |
| 限量闸 | 首列来的词每册至多 1 题 | **误杀好题**——「内气口」「外气口」也在首列，它们是真好题 |
| **弱题标记** | 照出、打 `weak=True`、判分时排除、单列统计 | **采用** |

**为什么选第三条**：栏目名（注意／用法／来源／主事）与真术语（纳气／木型／内气口）
在字面上分不开——都是 2 字抽象词，一个答得出、一个答不出。既然自动分不开，
就不硬判：照出、标记、判分时排除。**宁可标弱，不可杀错，也不可混算。**

## 2. 基线：从 1 册到 22 册

### 2.1 三条纪律

1. **卷子不带答案**。出卷导出两个文件：`paper.json` 只有题面，`key.json` 锁答案。
   作答阶段只给 `paper.json`。把答案跟题面放一个文件，等于闭卷考试把答案印在卷头。
2. **盲测要标**。模型对四柱基础本来就有先验，「闭卷」只能保证**没看答案**，
   保证不了**没学过**。读过、参与撰写过的册必须标 `blind=False`，报告里分档统计。
3. **出不了题的册要登记**。散文体册页挖不出空，硬出题只出废题。这类册不是
   「已掌握」，是**盲区**，必须单列，不能从分母里悄悄消失。

### 2.2 真实结果（2026-11-05）

| 项 | 值 |
|---|---|
| 已测 | **22 册**（盲测 21／非盲 1） |
| 平均掌握 | **0.6772**（盲测 0.6618／非盲 1.0000） |
| 档分布 | 熟 8／半熟 11／生 3 |
| 最薄 | `08` 风水 0.44、`41` 打分引擎 0.45、`49` 干支关系 0.47 |

**非盲那一册拿 1.00，盲测最高 1.00、最低 0.44**——这个落差本身就是
「分档统计」的理由。混在一起算平均，等于把背书当成掌握。

### 2.3 一个判卷器缺陷：别名一律判错

首轮判完，错题里有一批不是不会，是**同义不同名**：

- `49` 册「半三合」答成「半合」→ 判错。字面上「半合」确实不是「半三合」的子串。
- `22` 册「大运」答成「大限」→ 判错。紫微说大限、四柱说大运，同一步十年运。
- `43` 册「偏旺」答成「偏强」→ 判错，而 `43` 册自己写着「是同一档的别名」。

判卷是字面比对，同一概念两套叫法一律判错，掌握度就**系统性虚低**——
测出来的是「背没背原话」，不是「懂没懂」。

治法：`skills/xuanjian-kb/aliases.json` 别名表，同组任一写法算全对，
结果标 `via_alias=true` 可查。**同时立红线**：别名只解决同义不同名，不解决语义错——
`用神`≠`忌神`、`身强`≠`身弱`、`太弱`≠`从弱`（`43` 明说两档取用方向不同），
这些写在 `not_aliases` 里，字面再近也不放过。

修正幅度：盲测 0.6285 → **0.6618**（+3.3pp），`49` 册 0.37 → 0.47。

## 3. 裁决：提案没有消费端，等于没提案

### 3.1 症状

`distill.py` 报 NEW 179／REVIEW 44／KNOWN 3。数字像大丰收，实际**一条也没进库**。
提案攒得越多越像成绩，其实一行知识都没落。

### 3.2 `ruling.py` 的三条纪律

1. **不许一键全采纳**。`裁` 只接受单条 id，没有 `--all`。
2. **每条必须写理由**。没理由的裁决不算裁决，只算点头。往后回看「当初为什么驳回」
   比「驳回了什么」更有用。
3. **已裁不许重裁**。同一条裁两次会让台账自相矛盾；要改口用 `改判`，旧条标
   `superseded` 保留，不删——**留痕**。

### 3.3 第四件事：判新 ≠ 判值不值

第一轮裁到第七条就看清了：179 条 NEW 里大半是课堂口语碎片——
「答：戊申，己酉大运不能改变…」脱离上下文没有价值。

`distill` 的 `对撞` 判的是**字面相似度**：库里找不找得到相近说法。找不到就是 NEW，
这个判定没错。错在把 NEW 当成「该入库」。

于是给 `distill` 加 `admission` 四级：

| 级 | 判据 |
|---|---|
| 规程 | 14–140 字、含判据词（要／须／若／必须／不能…）、无具体年份、无口语标记 |
| 案例 | 含 19xx／20xx 年，或「答：」「分析：」「这个八字」等口语标记 |
| 碎片 | 不足 14 字，或无判据词（是陈述不是规程） |
| 长段 | 超 140 字，须人工摘句 |

实测分布：**规程 46／案例 41／碎片 139**。也就是说 226 条里真正值得逐条裁的
只有 46 条（20%）。**判新归相似度，判值不值归可入库性——两件事必须分开。**

## 4. 一条踩出来的教训：裁决必须在最新库上做

### 4.1 发生了什么

第一次跑 `distill` 时，库里还没有 `KB96`／`KB97`（那两册是提炼之后才写的），
于是 179 条判 NEW。裁到第 22 条后，重跑 `distill`——因为库里已有 96／97 两册，
同一批断言对撞到了自己的册页，**NEW 179 → 121，KNOWN 3 → 33**。

重跑后核对台账 id，22 条全部仍对应原句（抽取顺序没变，只是判定变了）。但内容变了：
**我裁为「采纳」的 9 条里，有 5 条其实已经逐字写在 KB96／KB97 里**——

| id | 原裁 | 重跑对撞到 | 改判 |
|---|---|---|---|
| D171 | 采纳 | `KB97` L130 逐字有「婚姻宫主张静态不主张动态」 | 驳回 |
| D048 | 采纳 | `KB96` L86 逐字有「45 分是临界值，临界值时要考虑月令」 | 驳回 |
| D045 | 采纳 | `KB96` L82 逐字有「偏旺／偏弱／从弱 → 墓运不如调候大运」，相似 1.00 | 驳回 |
| D056 | 采纳 | `KB97` L15 已收亥午暗合机理 | 驳回 |
| D014 | 采纳 | `KB96` L129 已收「身强有食伤会反抗，身弱转抑郁」 | 驳回 |

### 4.2 立为规矩

**裁决前先重跑 `distill`，对着最新库判。** 库一变，昨天的新知识今天可能就是重复；
拿旧提案的判定去裁决，等于照着一张过期的地图找路。

配套：`改判` 不是失败，是**必要动作**。台账里 `superseded` 的旧条不删，
正是为了让「我改过口、为什么改」可查。

## 4·补. 第二条踩出来的教训：`--覆盖` 迁移盖掉了新进度

同一轮里还踩了一个，比上面那个更蠢：

**经过**：本轮开手第一件事，为「确保状态干净」跑了一遍
`study_state.py 迁移 --到 当前工作区 --覆盖`。结果把当前工作区里**刚写好的进度**
原样盖回旧库的版本——摄取台账 **67 → 65**（第 45、52 两课登记蒸发），
进化日志**丢了一整行**（1.55.0）。

**为什么备份没救回来**：迁移确实留了 `.bak-时间戳`，但备份的是**被覆盖前的目标**，
而目标被覆盖时已经是最新状态；备份在，只是我当时没意识到要去看。
**「有备份」不等于「该覆盖」。**

**治法**：给迁移加一道闸——**目标文件比源更新，一律拒覆盖**，结果里单列
`refused_newer` 留痕。理由很直白：目标比源新，说明它装着源里没有的东西，
所谓「覆盖」其实是在删新东西。

```
if 覆盖 and os.path.exists(d) and os.path.getmtime(d) > os.path.getmtime(s) + 1:
    拒绝.append(名)
    continue
```

**顺带立一条操作纪律**：迁移只在换工作区时跑一次，且**默认不带 `--覆盖`**；
带 `--覆盖` 必须能说清「目标里那份为什么该被丢掉」。

**已回补**：台账重新登记两课（65 → 67），进化日志从备份取回 1.55.0 行。
自检 `study_state.py --selftest` 13 条里新增 3 条专测这道闸。

### 5.1 落册的六条，为什么是它们

- **印运守档**（`KB96` §3.7）：`37` 只讲「原局是既定状态」总纲，没落到印运这一档。
  印是唯一直接扶起日元的十神，一动就可能改档，所以第一顺位是守档不是用印。
- **伤官主伤病**（`KB96` §3.8）：`55` 讲伤官心性、`51` 讲十神正负面，都没把伤官
  和伤病挂上。本课挂上了，且给了两个条件（引动原局／为忌更甚）。
- **半三合级别**（`KB97` §1.3）：`KB97` 原先只讲了暗合垫底，没立半三合在六合之后。
- **打分算例**（`41` §4.6）：「亥水月取最低值 30 分」是口述口径，算子表里没有；
  没这个前提，同组干支能算出 60 也能算出 90，**差一整档**。

### 5.2 驳掉的四十五类，归成三种

1. **已在册**（最多）：KB96／KB97 逐字有，只是措辞不同被判 NEW。
2. **个案**：具体年份、具体某人的推演，无普适判据。
3. **提问**：抽取把「请问…？」当成了断言——`D042`／`D098`／`D219`／`D221`
   都是问句。这是 `distill` 的一个待修缺陷：**问句不该进候选**。

## 6. 硬约束

1. **掌握度不参与判档、不进 `score.py`**。它是学习指标，不是命理结论。
2. **弱题不进掌握度**。答错不代表不会，答对不代表会，混算只会两头失真。
3. **别名不解决语义错**。反义与错档写在 `not_aliases`，字面再近也判错。
4. **裁决必须写理由、必须对最新库**。无理由的裁决不算裁决。
5. **未裁的 175 条不许当成「已处理」**。台账写多少就是多少，覆盖率 22.6% 不许报成完成。

## 8. 复测：新语料有没有变成本事（v1.70.0）

`C5` 一直挂着：22 册基线是 v1.56 的旧账，之后馆里又吃进 1,297 份语料、写了十几册，
**但掌握度没再测过**。本轮按同口径重测 20 册（取原 22 册里题数 ≥4 的，避开 3 题以下的噪声）。

### 怎么测

- 卷子重出，**不看答案**；判卷也只给 `qid → 我的答案`，`key.json` 全程没打开；
- 20 册 × 8 题 = **160 题**，全部作答，未答 0；
- 盲测标记如实：`41`／`KB95` 本馆参与撰写、近期改过 → 标**非盲**，其余 18 册标盲测。

### 结果

| 项 | 值 |
|---|---|
| 重测 20 册，老均值 → 新均值 | **0.6649 → 0.6440（−0.021）** |
| 升／降 | 8 升／12 降 |
| 单册 \|Δ\| 中位数 | **0.075**（最大 0.417） |
| 档位变动 | 6 册（3 升 3 降）：33 熟→半熟、46 熟→半熟、50 半熟→生；43 半熟→熟、49 生→半熟、41 生→半熟 |

**结论：没有可测量的提升。** 变化量 −0.021 小于单册波动中位数 0.075，
按噪音看，这一轮既不能说「变强」也不能说「变差」——**能说的只有一句：新语料没有变成本事。**

### 为什么没变

题是从**册页正文**挖的空，答案是册页里的原词。新语料进的是引证库与采集账，
**没有并进这 20 册的正文**——册页没改，题就没变，测的还是原来那份记。
语料再多，只要不落到册页上，掌握度不会动一分。

这正是 `C5` 想问的：**堆文本 ≠ 长本事**。本轮给出了实测，而不是一句判断。

### 顺手修的一处断链

判卷跑完**不会自己进掌握度**：`落册()` 只是个函数，CLI 里没有命令。
于是「判过卷」和「掌握度里记着」是两件事，中间靠人记得另开 python 会话 import 才能接。
本轮加了 `--落册`（自检 19→25，含「history 只追加不覆盖」一条），流水线才真正闭合。

### 一个必须说清的边界

- **单册分数不稳定**：50 册从 0.567 掉到 0.150（8 题全错），不是「一夜忘光」，
  是这册的题面换了一批（旧卷 6 题／新卷 8 题），问到的点不同。**逐册差值不宜当结论**，
  只有总体方向可参考。
- 盲测只保证「作答时没看答案、没翻册页」，保证不了「没学过」——
  这批册我在历史轮次里参与过撰写，所以这是**闭卷复述**，不是零基础学习效果。

### 数据卫生：history 里两种格式、同日重复

本轮落册两遍（先全标盲测，后按真实标记重来），`history` 涨到 62 条，翻出两个旧毛病：

1. **同日同册重复**：`落册` 每跑一次追加一条，同日重测就叠一条。现在按 (日期, 册) 去重、**留最后一条**；
   同日改动前的值只在 `掌握度.json.bak-复测前` 里——**要对比同日前后，得比备份，不能比 history**。
2. **两种格式并存**：有一条形如 `{date, books:[…], 掌握度:{…}}`，是更早的批量写法，
   与逐条 `{date, book, score}` 混在一起，统计时 `x["book"]` 直接 `KeyError`。
   已按册拆成一册一条，并标 `migrated: old-format` 留痕。

清理后 `history` 22 条（每册一条，全部含 `book`）。**这类错不报错，只让「拿 history 算趋势」的人当场崩。**
