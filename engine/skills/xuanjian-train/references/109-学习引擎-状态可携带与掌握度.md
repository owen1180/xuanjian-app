# 一百零九、学习引擎（状态可携带、提炼半自动、掌握度可测）

> 定于 2026-11-05。本册记录「学习能力」这条线从「有流水线」到「有闭环」的改造，
> 以及改造中被数据打脸的三处。
> 一句话结论：**之前的学习只有摄取、没有掌握；只有进度、没有留存；只有机器、没有便携。**

## 二、四个新件

| 件 | 管什么 | 一句话 |
|---|---|---|
| `study_state.py` | 学习状态根 | 台账／基准／日志／掌握度四件统一解析、校验、初始化、迁移 |
| `distill.py` | 提炼 | 从原文抽候选断言，与既有册库对撞成 NEW／REVIEW／KNOWN／CONFLICT |
| `mastery.py` | 掌握度 | 从册页挖空出题、判卷、按掌握排下次复习日 |
| `study.py` | 编排 | 状态／下一批／提炼／出题／判卷／复盘，一条命令走完 |

### 2.1 `study_state.py`：四件一套，可搬

解析顺序：环境变量 `玄鉴学习` → `命理档案` → 向上找工作区 `命理档案/方法论` → 旧默认 → `~/玄鉴学习状态` 兜底。

**不做静默迁移**：核到旧根有、新根没有，只提示跑 `迁移`，不在读操作里偷偷写盘。
`迁移` 先搬后补空壳——首版反过来，先 `初始化` 造了空壳，搬家时全判「已存在」，
**迁移报成功却一个字没搬**。这个坑记在这里，因为它是「顺序错了但结果看起来对」的典型。

### 2.2 `distill.py`：只提案，不裁决

三类判定：

| 判 | 条件 | 处置 |
|---|---|---|
| `KNOWN` | 库中同术语句的 2-gram 包含度 ≥ 0.60 | 省去重写，记对应册页 |
| `REVIEW` | 0.30–0.60 | 需人确认是否同一件事 |
| `NEW` | < 0.30 | 新知识候选，人核定后才落册 |
| `CONFLICT` | **判档分数（「分」）**不一致，或本句立禁令而库中同术语句为肯定 | **必须人裁，一条都不许自动采用** |

三处口径是调出来的，不是拍出来的：

1. **相似度用包含度，不用 Jaccard**。库里的句子比课程口语长得多，Jaccard 被长短差吃掉，
   首轮 226 条候选全判 NEW（KNOWN 为 0）——明明讲过也判成新知识。
2. **数值冲突只认「分」**。首版把年、岁、个数也算冲突，跑出四条误报：
   「2012年」对「十年」、「两个寿元星」对「一个」——两句话讲的根本不是同一件事。
   年／岁／个是**个案细节**，不是**口径**；只有判档分数不同才是口径打架。
3. **中文数词要能转阿拉伯**。「六十分」与「60 分」必须同口径，否则阈值比对形同虚设。

### 2.3 `mastery.py`：挖空，不问答

**为什么不用问答题**：第一版让脚本生成「X 指的是什么」，抽出的是
「『原因』指的是什么？」这类废题——从散文自动造问句，问的是表头不是知识。

改成**挖空**：从带判据（分数／寸／天／岁）或带术语的句子里挖掉那一段，
**题面是原句，答案是被挖的原文片段**，判卷是归一化后的精确比对。没有歧义，也骗不了自己。

三道判断：

- `hit`：填对（归一化后相等或互为子串）
- `grounded`：作答的字在册页里查得到——防「说得像、书上没有」
- `掌握度` = hit×0.6 + grounded×0.4；**禁令题答成肯定句（越界）直接判零**

复习间隔 1／3／7／21／60 天，掌握度跌破 0.60 回到第一档。

题源限制三条（都是踩出来的）：元信息章节（开册留痕、引用标号、版本说明）跳过；
表格行折成一句再挖；同一句里出现两次的片段不挖（挖了也对不准是哪一个）。

### 3.3 掌握度（闭卷实测）

拿 `38` 合婚册（本轮之前未读）出 8 道挖空题，闭卷作答：

| 结果 | 数 |
|---|---|
| 命中 | 5 / 8 |
| 有据 | 5 |
| 越界 | 0 |
| **掌握度** | **0.625（半熟）** |
| 下次复习 | 2026-11-08 |

三处错里有两处是同一个错：标准答案「婚姻宫」，作答写「夫妻宫」。

**这条比分数有价值**：四柱用**婚姻宫**（`38` 六处、`54` 十六处），紫微用**夫妻宫**（`11`、`22`、`36`）。
意思没错、术语归错体系。已写进 `KB96` §5 立分界——混用的后果不是错一个字，
是交叉核对时分不清结论出自哪一路盘。

第三处错在「48 岁」答成「中年」：**能说方向、说不出精确岁数**，与本馆「不断具体日期」的
红线同源，不算硬伤，但说明该册的限运细节还没进掌握。

### 3.4 一句实话

掌握度只测了 1 册，不足以说明整体。**67 册里 66 册仍无掌握数据**——
这不是「已掌握」，是「未测」。报数字时两者不能混。

## 四、学习闭环（固定七步）

```
① study.py 下一批        → 排该读什么
② ingest.py 批量 …       → 取回原文（存 .workbuddy/learning/raw/）
③ study.py 提炼 <原文>   → 抽候选（NEW/REVIEW/KNOWN/CONFLICT）
④ 人裁决 + 写册           → 只写核过的；CONFLICT 必须人裁
⑤ ledger.py 登记 <标题> <册号>   → 登记才算读完
⑥ study.py 出题 <册号> → 人作答 → study.py 判卷   → 得掌握度与下次复习日
⑦ study.py 复盘          → 进度 + 薄弱册 + 待裁候选 + 到期复习
```

第 ④ 步永远是人。本册不含任何「自动写册」的入口——术数的内容判断不交给脚本，
这条从 `TR100` 立到 `TR109` 没动过。

## 五、四条铁律（新增，与既有铁律并列）

1. **状态必须可携带**。学习进度写在专家包之外的单一状态根里，换工作区先跑 `迁移`。
   状态绑死在某个路径上，等于每次搬家都把学问丢一遍。
2. **读了要能答才算读过**。台账的「已摄取」只表示**材料处理过**，不表示**掌握**；
   对外报进度必须同时报已测册数与平均掌握度，两个数不能只报好看的那个。
3. **提炼可以半自动，裁决不能自动**。脚本负责「抄」和「比」，人负责「断」。
   `CONFLICT` 一条都不许自动采用，`NEW` 未核定不许落册。
4. **掌握度不许凑**。阈值不因结果难看而放宽；挖空题答错就是答错，
   语义相近但术语归错体系（婚姻宫／夫妻宫）也判错——**判松了，测的就不是掌握**。

## 六、已知限制（不藏）

| 限制 | 说明 |
|---|---|
| 挖空是**线索回忆**，不是自由回忆 | 题面给了上下文，比「从零复述」容易；掌握度是**上限偏高**的估计 |
| 判卷是**字面**比对 | 意思对、措辞不同会判错，结果**偏保守**；两个偏差方向相反，不互相抵消，别当精确值 |
| 题源依赖**结构化程度** | 表格与判据句多的册出题好；纯散文册出题少甚至为零 |
| 只适合**逐册**测 | 跨册综合能力（如「同时用三册判一个盘」）测不出来，那要靠案例库（`TR106`） |
| 掌握度**不参与判档** | 它只影响「下一轮先复习哪册」，绝不进 `score.py`，也不影响任何断语 |
