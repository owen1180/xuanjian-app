# 119 · 跑过才算过，查到才算覆盖

> 承接 `TR118`（判据的代价）。那一轮把引证闸的误杀从 86% 压到 0。
> 本轮换一个方向问：**「两闸都跑了」这句话，谁来验？**
> 顺手把三个一直没自检的脚本补齐，撞出两个真 bug；再把引文回查的覆盖面量了一遍。

## 一、「都跑了」是句没有主语的话

`TR117` 立规：发出前 `kb_gate`（红线闸）与 `source_gate`（引证闸）都要跑。
规矩清楚，执行靠人。而人是这样跑的：

```
跑 kb_gate → PASS → 交稿
```

引证闸呢？**没跑。** 但报告上写的是「已过闸门」。这不是撒谎，
是那句话本来就没有主语——**「闸门过了」可以指「我跑的那道过了」。**

更坏的一种本馆真的栽过：`evolve.两道闸()` 在闸门不在时用 `all([])` 判断，
空序列恒为真，于是「一个闸门都没跑」被报成「全部通过」。
**没跑到等于通过**，这句话不是修辞，是一行代码。

## 二、把「没跑」拆成一种状态，且它不算通过

新增 `openbook/scripts/preflight.py`（`发出前`）。它只做三件事：

1. 依次跑两道闸，每道都记「跑没跑、结论是什么、为什么」；
2. 状态分成四种，**只有第一种能算过**：

| 状态 | 含义 | 算不算过 |
|---|---|---|
| 已跑 | 跑完拿到结论，放行或拦下都算 | 放行才算 |
| 未跑 | 闸门模块不在、缺必需输入，根本没执行 | **不算** |
| 炸了 | 执行了但抛异常，结论不可知 | **不算** |
| 没核到 | 跑了，但缺引证库／语料，该核的没核 | **不算** |

3. 给一张回执：稿件指纹（sha1 前 8）、字数、每闸状态、时间、退出码。
   事后能回答「当时发出去的那一版，究竟过了哪两闸」，不必凭记忆。

退出码：`0` 全过／`1` 有闸明确拦下／`2` 没有拦下但有闸没跑成。
**2 和 1 都是「不得发出」，但处置不同**：1 要改稿，2 要补条件。

`没核到` 这一档是 `source_gate` 逼出来的：它在缺引证库时只出一条
`NO_QUOTE_INDEX` warning，其余照常判。汇总处若只看 `error_count == 0`，
这道闸会在最该拦的地方变绿。**闸门说「我没法核」，汇总处必须翻译成「没核到」。**

## 三、三个踩出来的坑

**坑一：空表退 0。** 自检里写「一道闸都没有时应退 2」，第一版没通过——
`any()` 对空序列为假，于是「没有闸」走到 `return 0`。
**同一个 `all([])` 家族，换个函数又犯一次。** 现在显式判断 `if not 果`。

**坑二：`bool(None)` 把「没法核」压成「拦下」。** 闸门用 `None` 表示「我核不了」，
汇总处 `bool(放行)` 一压就成了 `False`。两个状态在回执里处置不同
（拦下要改稿，没法核要补库），压平就再也分不出来。现在保留 `None`。

**坑三：中文环境变量传不进去。** 本馆一直用 `命理档案=<档案根>` 传路径。
实测：

```python
os.environ.get('命理档案')      # → None
```

`命理档案=/x python3 …` 在本机 shell 里根本没进环境。**中文变量名不是所有
shell、所有调用链都认。** 只认它＝静默失效，闸门于是报「没库」，
汇总处再当绿灯放过——**又是一条「没跑等于通过」，只是藏在配置里。**

处置：`source_gate.找引证库()` 自己找——环境变量 → 从稿件目录向上找 →
从当前目录向上找 → 工作区同级 `~/WorkBuddy/*/命理档案/引证库/索引.json`（取最新改的）。
`preflight` 不再自己写一份，改为**委托**它。两处各写一份，迟早分叉：
一处修了中文变量的问题，另一处没修，同一份稿在这道闸能核、在那道闸不能核。

还有一条反向的：**显式 `--引证库` 给了坏路径，不许偷偷换别的库顶上。**
换掉之后「人指的那个库」与「实际核的库」不是一回事，人以为核过了，
核的却是别处那份。路错就返回 `None`，让闸报「没核到」，人自己看见。

## 四、三个补自检的脚本，撞出两个真 bug

`selftest_gate.py 盘点` 一直点着三个 200 行以上、没有一条自检的脚本。
补的过程比结果有用：

| 脚本 | 自检 | 撞出什么 |
|---|---|---|
| `archive/kb_ledger.py` | 23 | **`暂无数据` 那一行永远不出来** |
| `ritual/query.py` | 19 | **「城隍牒／城隍符」挂在科仪层** |
| `kb/fangji_index.py` | 20 | 去重逻辑埋在 `main()` 里，测不到，抽出 `去重()` |

**bug 一（台账空表）。** 汇总报告的代码是：

```python
if len(lines) == 7:          # 「一条规则都没写」时补一行「暂无数据」
    lines.append("| （暂无数据） | … |")
```

表头一改，行数就不再等于 7。空台账渲染出来是一张**只有表头、没有一行**的表，
看着像 Markdown 坏了。现在改成数「写了几行」，不数 `len(lines)`。
**用行数当业务判断，等于把排版当逻辑。**

**bug 二（场景表挂错层）。** `query.py 场景 官非` 的「科仪」层里列着
「城隍牒／城隍符」。数据里它在 `fulu.json`（符），不在 `keyi.json`。
新自检做了一件以前没人做的事：**逐条核场景表引用的名字在不在对应数据表里**。
第一次跑就报了三处悬空——其中两处是「孝亲与祭祖」这类善行大类（本就不对应
单一功格条目，单列白名单），另一处就是这条挂错层的。
用户点「官非」会看见一个科仪层里的符，**点进去找不到做法**。

自检里那条断言现在长这样：

```python
查("场景表·科仪符无悬空引用", 悬空 == [])
```

失败的说明会把「场景[官非]科仪→城隍牒／城隍符」直接点出来。
**这种洞不报错、不崩，只是静默少一行**，靠人眼永远发现不了。

## 五、引文回查：把「八个字」读成了「八段」

`kb/verify_quotes.py` 判断一条引文该不该收，用的是：

```python
if len(CJK.findall(q)) >= 8:      # 看着像「至少八个汉字」
```

`CJK` 是 `[\u4e00-\u9fff]+`，`findall` 返回的是**匹配段的列表**。
一句没标点的引文只算 1 段，`1 >= 8` 为假，**整句被静默丢掉**。
只有逗号够多、凑满八段的长句才碰巧漏过去——所以这脚本一直「能跑」，
只是悄悄少收了大半引文。改成 `汉字数(q) >= 8` 之后，同一批册页
从「抽到 0 条」变成「抽到 98 条」。

同一处还有两个哑巴坑：

- **只认 `.txt` 语料**。本馆自己采的 1,297 份语料由 `harvest.py` 定出成 `.md`，
  于是对着自己的语料跑，永远得到「语料为空」——**不是没语料，是没认出来**。
- **只认 `原文："…"`，不认 `原文：「…」`**。册页里最常见的就是「」。

**判据漏了一种写法，等于那一类引文从来没核过。**

## 六、未见要分六种，「未纳入」要单独报

早前只有「命中／待查」两档，一次跑出四十几条待查，人看两遍就不看了。
问题在**其中大半本来就查不到**：那本书是扫描件、没 OCR，哪来的原文可对？
把它们和真问题混在一张表上，等于让真问题淹没。

现在每条未见先归因，归因读的是**引证库同一份档位**（不再另立一套判据）：

| 归因 | 判据 | 处置 |
|---|---|---|
| 真待查 | 书在库、档位「可逐字引」，句子对不上 | **这才要看** |
| 本无原文 | 书在库、档位「仅指认／近空／散图／乱码」 | 正常 |
| 无电子本 | 白名单典籍（《滴天髓》《撼龙经》） | 正常，须给篇卷 |
| 课程引文 | 附近有 `第52课`／`L58`／`.docx.md` | 按课程语料核，不按书名 |
| 书目存疑 | 引证库和白名单都没有 | 补进去或删掉 |
| 无书名 | 三行内无书名、无课次 | 说不出出处，无从核 |

「课程引文」这一类是量出来的：第一版把 41 条散在正文里的引文全归「无书名」，
翻了两册才发现——**它们都按课次引，抬头第 3 行就写着「第 52 课」**。
改成「附近三行 → 整册抬头八行」逐层兜底后，无书名从 41 降到 8。

**抬头只取课次，不取书名。** 抬头里的书名常是「本册拿来对比的那本书」，
拿来认领会把出处张冠李戴；课次是整册共用的，不会认错。

还有第四种「看不见的漏」，单列：**未纳入**。全库 135 册实测：

```
可核格式引文      98 条（命中 53，54%）
散在叙述的长引  2,548 条 ← 本工具根本没抽到
```

只报前者的命中率，是把 30% 的覆盖说成 100% 的干净。
（此处原写「2,548 条、4% 覆盖」，**数错了**，勘误见本节末。）
所以报表第一句就写未纳入条数，并且**一条可核引文都没抽到时，结论写
「不是通过，是没有可核对象」**，不许写「无真待查」。

### 勘误：那个 2,548 是怎么来的（v1.68.0）

第一版量「未纳入」用的正则是 `"([^"]{12,})"`——**允许跨行，且把 ASCII 双引号当引号**。
册页里 ASCII 双引号大量用作**术语强调**（`把"得令得地得势"凭感觉`、`"另一套"`），
一句话里双引号个数为奇数时，配对就落到两个不相干的引号上，
于是**从引号到引号之间的一切**（标题、表格、整段正文）都被算成「一条长引」。

实测：同一批册子按「不跨行」重算 901 条，再只认「」与“”（册页里真正标原话的两种）
只剩 **230 条**。原来那个 2,548 不是引文数，是「引号之间的跨度数」。

**一个统计口径错了，不报错，只会把结论说大 11 倍。**
更该记的是：我拿这个错数做了两轮汇报，还据此立了一条待办（B4）。
判据的错分两种——**把对的判成错（误杀）会被发现；把错的量成对（错量）不会**，
它只会让所有下游结论一起偏，且看起来很具体、很像真的。

## 十、补记：档案根只能有一个（v1.68.0）

九、第一条点名的 C6，紧接着做了。做法与理由：

**病**：五个脚本各自解析档案根——`study_state`（状态根）、`regress`（写死旧路径）、
`evolve`／`ledger`（走 `study_state` 但带写死回退）、`quote_index`（只认环境变量与 cwd）。
同一天在同一个工作区跑，五个脚本可能落在三个不同的根上。

**为什么会落错**：中文环境变量 `命理档案=<路径>` 在本机 shell 传不进去（实测取到 `None`），
而「向上找工作区」只在「当前目录在工作区之内」时成立。于是**在专家包目录里跑任何脚本**，
前三层全落空，直接掉到写死的 `2026-10-26-…/命理档案`。

**最刺眼的一处**：`quote_index.读取舍()` 只认环境变量与 cwd，在包目录里跑返回 `{}`，
`标取舍()` 静默空转——**引文卡的「首选／备用」标记一条都不会打上**，
而 `source_gate` 校验行号时正是靠这个标记挑「首选那版」；标记缺失，它就去核列表里第一个，
**可能正好是乱码版或插了空格那版**。

**改法**：`study_state` 加第 4 层「最近改过的工作区」（`~/WorkBuddy/*/命理档案`，
按 `方法论` 目录 mtime 取最新），并新增 `根说明()` 返回 `(根, 依据)`——
**「回落到 X」必须带依据**，不然人没法判断该不该改到别处。
`regress`／`quote_index` 改为委托 `study_state`，`preflight` 的两闸也走同一条路。

**核过的账**（不夸大）：现有 `索引.json` 里 17 条取舍标记是齐的，重算零变化——
**这个坑目前没污染数据**，它只是等着下一次从包目录重建索引时才发作。修的是「等着发作」。

**自检**从 13 条补到 **25 条**，四层优先级逐层钉死。第一版写了「若真机候选里不含旧默认才断言」，
结果真机候选里正好含旧默认，**条件被跳过、测试看着绿一条没跑**——当场改成
monkeypatch 掉候选与向上找再断言。两组变异（去掉第 4 层／排序反了）全红。

## 十一、补记：台账把引证闸也记下来（C7）

`kb_ledger 记录` 原来只记红线闸，**引证那一道完全不进账**。报告上写「已过闸门」，
翻台账只见一道——事后查不出漏了哪道。

改法有三条纪律：

1. **只记不判**：`decision` 仍由红线闸定，引证结果单列 `cite_ok`／`cite_errors`／
   `cite_codes`／`cite_note`；真正「两闸都过才算过」由 `preflight` 把关，职责不混。
2. **`null` 是独立取值**：引证闸没跑成或抛异常，`cite_ok` 记 `null` 并把异常写进 `cite_note`，
   **不许写 `false`（那是拦下）也不许写 `true`**。
3. **措辞不许含混**：只过一道时，末行不再写「PASS → 可交付」，改写
   「PASS（仅红线闸）→ 单闸通过，不等于可交付」。台账这一行将来是要当证据用的。

`汇总` 新增「二、引证闸」一节：通过／未过／没跑成三分，未过按判据码计数；
老台账没有这个字段时**明写「没有一条记过，不等于都过了」**，不并入通过。
自检 23 → **31** 条。

## 十二、补记：B2 那批「规程×NEW」被判废是判错的（v1.69.0）

上一轮把 **4,283 条「规程×NEW」**整批挡在池外，理由写在待办看板上：

> 抽查「新术语」全是「午亥／庚乙」这类干支组合，一个真概念都没有。

**这个理由站不住。** 看的是 `terms` 字段——抽出来的关键词本来就是干支，它是索引不是内容。
翻回 `text` 原句，里面大量是真规矩：

```
大运可以影响八字，不能影响流年
专旺必须是全局没有一个泄耗，就算有也被合化成印比五行
如果是调候用神，但是是伏抑忌神，就是平运，不好不坏
不管天干地支的阴阳，只要是地支生天干，天干都叫实透，只要天干生地支，是虚透
```

**拿元数据判定内容，是「错量」的第三种长相**：不报错、不误杀某一条，
而是**把一整批真东西当废料倒掉**，而且倒得很有理由。

### 口径：只分层，不判真伪

`distill.py` 新增 `筛规程`，一条一句，按四件可数的事打分（7 分制）：

- 长度：≥24 字 2 分／16–23 字 1 分／＜16 字 0 分（**且总分封顶 4**——"不能从"这种半截话，语气词再全也成不了规程）；
- 规则语气：必须／不能／只要／才…／代表／说明／凡／皆／一律 2 分；
- 无第二人称、无具体年份分数、非问句：各 1 分；
- **域内闸**：命理术语 ≥2 个，或 ≥1 个且不沾中医词；**名著人物一票否决**（讲《西游记》的段落，不因为提到「八字」就成了命理规程）。
