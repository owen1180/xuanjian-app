# 一百零八、全库册号命名空间与成员挂载闸门

*2026-11-04 · v1.54.0「第十五轮 · 查漏补缺」新增。本册是**工程规程**，不新增任何断法、不改任何定案级规则。*

---

## 1. 为什么有这一册：一次真实的静默误读风险

v1.51.0 把开源三阶段核验的册页编为 `OB95`–`OB99`，放在 `xuanjian-openbook/references/`；
而 v1.50.0 已有一册 `skills/xuanjian-kb/references/95-四柱-格局专论-八格专旺两气成象与库四态.md`。

于是全库同时存在两个 95：

| 全名 | 内容 | 谁会引用 |
|---|---|---|
| `KB95` | 八格／一气专旺五格／两气成象／库四态，讲「这盘有没有格、格破没破」 | 知微、主理人报成色时 |
| `OB95` | 五个 404 路径、宣传计数失真、四段许可防火墙、真一 73% 自报 | 有人报 GitHub 项目时 |

主理人速查表与知识底座查表当时都把裸号 95 当作「开源三阶段核验／核验总表」，
但按编号去 `xuanjian-kb/references/` 取文件，取到的是**四柱格局专论**。
这不是措辞不严谨，是**检索会取错文件**：问「这个项目能不能用」，读到的却是「墓运阳干身弱」。

既有的 `kb_audit.py` 只扫 `xuanjian-kb/references`，六项检查全 PASS，
**跨技能撞号完全在视野之外**。README 第 57 行早已写下「撞号不是手滑，是流程缺一道闸」，
本册与 `book_registry.py` 就是补上的那道闸。

> 裁决（2026-11-04）：**不改号、不合并、不删册**。两份 95 都是已发布内容，改号会让既有引用全部悬空；
> 改为建立命名空间，并把所有 95+ 引用强制加前缀。撞号本身登记为**已裁决例外**，
> 但任何**新出现**的未登记撞号，闸门一律判 FAIL。

## 2. 命名空间定案

| 前缀 | 技能 | 册号段 | 说明 |
|---|---|---|---|
| `KB` | `xuanjian-kb` | `1`–`94` 与 `KB95` | 知识底座。默认命名空间 |
| `OB` | `xuanjian-openbook` | `OB95`–`OB99` | 开源核验、口径卡、引证、评测、合参契约 |
| `TR` | `xuanjian-train` | `TR100`–`TR108` | 数据训练、全量研习、命名空间闸门 |
| `AR` | `xuanjian-archive` | — | 档案（暂无编号册页） |
| `EV` | `xuanjian-evolve` | — | 进化（暂无编号册页） |
| `RI` | `xuanjian-ritual` | — | 改运（暂无编号册页） |
| `SZ` | `shizhan-pai` | — | 实战排盘（暂无编号册页） |

三条硬规则：

1. **`1`–`94` 默认属 KB，可裸写**（如 `` `60` `` 即 KB60）。
2. **95 及以上一律带前缀**：`KB95`／`OB95`–`OB99`／`TR100`–`TR108`。
   写作裸号 95 即视作歧义，闸门判 AMBIGUOUS；写成 `OB95` 才准。
3. **带前缀引用必须真实存在**，写一个不存在的册号（例如 TR109）即判 DANGLING。

新增册页前：先跑 `book_registry.py` 看撞号表，再跑 `kb_audit.py --next` 看 KB 段下一个可用号；
**跨技能新增一律从全库最大号往后排**，不许各技能各编各的。

## 3. 闸门管四件事

`skills/xuanjian-openbook/scripts/book_registry.py`：

```bash
python3 book_registry.py                    # 全库报表
python3 book_registry.py --strict           # 发出前闸门，硬错误 exit 1
python3 book_registry.py --out reg.json     # 写 JSON 台账
python3 book_registry.py --selftest
```

| 检查 | 判级 | 为什么 |
|---|---|---|
| 跨技能撞号**未登记** | 硬错误 | 新撞号必须走裁决，不许静默并存 |
| 撞号号段的裸号引用 | 硬错误 AMBIGUOUS | 正是本轮出事的那一种 |
| 95+ 引用缺命名空间前缀 | 硬错误 | 防下一次撞号 |
| 带前缀引用指向不存在的册 | 硬错误 DANGLING | 防引用幻觉 |
| 成员引用了某技能册页但 `skills` 未挂载 | 硬错误 MOUNT_GAP | 防「规则写了，成员读不到」 |
| 非册号数字（年份、计数、百分比） | 忽略 | 只记数不判错，避免噪声淹没真问题 |

`COLLISION_POLICY` 是**撞号裁决台账**：登记过的撞号不判死，但强制带前缀。
这与「不许改基准消警报」不冲突——登记的是裁决与消歧方式，不是把问题抹掉。

## 4. 顺带订正的一处误报（不是改基准）

`kb_audit.py` 原报 `KB95` 一处告警：「出现『五格』，未见『不拿它断』一类限定」。
查证后是**检测器把两个「五格」混成一个**：

- 取名五格（三才五格数理）→ 受 `84` 约束，出场必须带「能算不断」的限定；
- **一气专旺五格／特殊五格**（八字格局专论，出自第二十八课「五格与库 案例分析」）→ 与取名毫无关系，不受该限定约束。

订正方式：在 `check_fences()` 给「五格」加八字格局语境白名单（出现「一气专旺／特殊五格／五格与库／专旺」且不含「取名／姓名学／三才／康熙」即跳过），
**不删词、不改册页正文、不放宽取名侧的限定**。这是分辨「订正」还是「回归」之后的订正，留痕于此。

## 5. 成员挂载：规则写了，成员得读得到

本轮另查出：十位成员的 frontmatter 一律是 `skills: [xuanjian-kb]`，
而总纲第 16／17／21／22 条要求成员遵守口径卡（`OB96`）、引证闸门（`OB97`）、
独立派单（`OB99`／`TR104`）、图不量化（`TR105`）。**成员根本加载不到这些册页**——
规矩只写在了主理人身上，执行层是空的。

因此 v1.54.0 起：

- 全体成员挂载 `xuanjian-openbook`，取得口径卡、引证、合参契约的只读权限；
- 训练与可视化层不挂给成员（`TR` 归主理人调用），其约束以「派单契约」明文写进成员提示，避免成员越线去调训练脚本；
- 每位成员提示内新增统一「派单契约」小节，八条：口径卡只读、`no_peer_results`、先独立后互通、
  事实归工具、引一句查一句、归纳标〔本馆归纳〕＋覆盖自评、判档唯一 `score-py`、
  **本人终点永不可断／六亲敢断有无厚薄点具体人（R-033）**。

`scan_mounts()` 会在发出前检查「引用了某命名空间的册页却没挂载对应技能」，把这类真空变成机械错误。
