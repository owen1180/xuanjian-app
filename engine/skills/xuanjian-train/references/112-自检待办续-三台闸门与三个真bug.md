## 二、内容闸 `kb_gate.py`：红线挂在了召回上

### 2.1 兜底洞（最重）

原实现只在**被召回到的规则**范围内扫禁词。召回靠关键词命中，于是：

```
gate("我最近怎么样", "你必死，没有救了")   →  PASS
gate("我最近怎么样", "死别之象")           →  PASS
gate("我最近怎么样", "必死无疑")           →  PASS
```

原因：`「必死」「死别」不在任何一条规则的 recall 里`（K046 收的是「会不会死」「哪年走」，
K039 收的是「必发／必富／必贵」）。召回为空 → 逐条规则一条都不扫 → 零违规 → PASS。

**这是性质错误，不是精度问题**：红线成了「说了关键词才生效」的条款，不说关键词就能直穿。
治法：加 `类兜底` 表，八类禁词各有唯一归属规则，**不问召回、命中即拦**：

| 禁词类 | 兜底规则 |
|---|---|
| 生死禁词 | K046 寿元星零禁词 |
| 铁口禁词 | K039 用神级别与断语封顶 |
| 病名禁词 | K025 望诊零病名 |
| 医疗动作禁词 | K024 五术边界与就医触发 |
| 道德审判禁词 | K028 人事不做道德审判 |
| 宿命禁词 | K049 不传播宿命论 |
| 方药剂量禁词 | K050 方药／食疗剂量零承诺 |
| 灾祸断言禁词 | K051 理气阳宅灾祸不断言 |

纪律三条，都写成了用例：**每类必须有主**、**主必须确实管这一类**（在它的 `banned_cats` 里）、
**兜底违规要标 `禁词·兜底`**（可区分「召回到才拦」与「兜底扫到」）。经方通道的方药豁免，
兜底同样要守——否则从没召回的后门会绕开三句硬标记。

### 2.2 紫微「大限」被当生死禁词（误拦）

`撞车豁免` 原本用「命中位置前后各取 1 字」判合法词形，正则写的是 `[运紫]大限`。
可「紫微大限」三字里，「大限」前一字是**「微」**——窗口取不到「紫」，正则不匹配，
于是**紫微报告里一写「紫微大限」就被生死禁词拦下**。改成 `[运紫微]大限`，窗口放到前后各 2 字。

> 误拦比漏拦安全，但误拦会教人绕开闸门。闸门一旦被当成噪音，就等于不存在。

### 2.3 一处**只锁现状不改口径**：`require_phrase` 要求全部出现

现行实现里 `require_phrase` 是「**每个都得有**」，不是「有其一即可」。于是草稿写了
「建议就医」，仍会因缺「尽快就医」被拦（K050），K024 更要求「建议就医＋尽快就医＋体检」三句全背。

这确实偏严，但改它等于放宽红线，须先定案。本轮**不动口径**，只在自检里锁住现状并登记待办。
用例里那行样例特意写全三句，注释写明「这是现行口径，不是理想口径」。

## 三、册页自洽闸 `kb_audit.py`：三种安静的死法

补测时按「它可能怎么安静地坏」分三类，逐类设样本（全部在临时目录造，不碰真册页）：

1. **算错**——中文序数转换。`一百零八` 原实现算成 **100**（「零」之后的数字被丢）。
   当前册号还没过百，属潜伏错；百号之后必有此写法，先修。
2. **看不见**——`load_volumes` 只认 `数字-标题.md`，认不出的直接 `skip`。
   一个叫 `备注.md`／`2-乙.md.bak`／`99-待定.MD` 的文件可以整篇消失于所有检查：
   六项全绿，而那份册页根本没被读过。新增 `[7] 目录完整性` 专抓这类游离文件。
3. **判据太窄**——交叉引用原判据是 `r not in vols and r > max(vols)`，只报「比最大号还大的号」。
   册号一旦出现**断号**（某册被删或改名），指向那个断号的引用**一条都不会报**。
   改为 `r not in vols`，并新增 `[8] 册号连续性` 直接报断号。

另修一处静默：版本闸靠正则 `下 (\d+) 份 references` 读册数，**读不到就跳过**——
README 换个说法，这台闸就再也没读过册数。现在读不到即报「册数无从校对」。

真库复核：97 册、无重号、无断号、无游离文件、八道闸全绿。

## 四、排盘引擎 `pillar.py`：夜子时双重进位（本轮最重）

### 4.1 症状

```
$ python3 pillar.py 1957 10 1 --hour 23 --minute 30 --sex 女
注意：真太阳时已过夜子时，日柱按次日推算
警示：时柱两算法不一致（库=壬子，五鼠遁=庚子），请人工判定
四柱：丁酉　己酉　丁未　壬子      ← 时柱错
天干十神：年比肩 月食神 时正官    ← 十神跟着错（应为正财）
```

### 4.2 病因

本脚本口径是「过了 23 点，日柱按次日推算」，所以 `dGZ` 拿到的是**次日**日干；
而 `sxtwl.getShiGz(日干, 23)` 在 23 点还会**自己再进一天**。两次进位叠加：

- 当日 丁未 → 日柱按次日取 **丁未**（本例次日恰为丁未，视觉上不易察觉）
- 时柱问库：库认为 23 点属次日之子时 → 再进一日 → 给 **戊日子时＝壬子**
- 正确应为 **丁日子时＝庚子**

**整整错一天**，且时干十神从「正财」错成「正官」——一份四柱报告的两处硬结论同时错。

### 4.3 为什么它能活这么久

脚本其实**知道**不一致：它会打印一行「警示：时柱两算法不一致」。但那只是 `print`，
**进程照样退 0**，四柱照出，报告照写。这正是 `TR111` 里「失败不落地」那一型——
只不过落地的不是自检，是运行时的告警。

### 4.4 修法

把时柱判定抽成纯函数 `定时柱(日干, 小时, 夜子时)`：夜子时走五鼠遁（日干已定，不再问库）；
非夜子时仍问库，但**库给的时支与本地口径不符时以本地口径为准**。

自检把 0–22 点做成 **110 组全量断言**（两算法必须逐组相同），把 23 点这一格做成
**结构性断言**（库比本地多进一天，甲日：库丙子 vs 手甲子），并直接钉死
`定时柱("丁", 23, True) == "庚子"`。三组一起，这条 bug 回归不了。

**存量影响**：出生时刻 ≥ 23:00 的盘时柱全错一天。本工作区暂无成品档案；其它工作区的
盘须回查，待办见 §7。

## 五、变异测试账

`TR111` 立的规矩：新自检一律做变异测试，只加断言不验灵敏度等于给门装假锁。本轮三台：

| 闸门 | 变异组 | 首轮未抓到 | 处置 |
|---|---|---|---|
| `kb_gate` | 10 | **2**（K024 优先级降 1、经方少一句硬标记） | 都是「断言挂在结论上」：降优先级后判决仍 BLOCK，少一句后仍因缺提示语 BLOCK → 补「全表最高优先级是 K024」「`rx_ready` 三句逐个缺一句为假」 |
| `kb_audit` | 9 | 0 | — |
| `pillar` | 4 | 0 | — |

「挂在结论上」是本轮最值得记的一句：**断言的落点要与机制同一层**。
决策是结论层，机制层是 `rx_ready`／`priority`。只断结论，变异就漏。

## 六、元闸抓自家

两件事都由 `selftest_gate.py` 当场抓出，说明它确实在管事：

1. **我自己写的恒真断言**——「同优先级时按表内顺序稳定」被写成
   `[r for r in f(x)] == [r for r in f(x)]`，两边是同一个表达式，永远为真。
   元闸报「恒真断言 1 处（行 634）」，改成与「按 `(-priority, RULES.index)` 显式排序」的结果比。
2. **`evolve.py` 的用例自身不一致**——它拿 1.56.0 的模板行去记 1.57.0，却断言文里出现
   `| 1.57.0 |`；随后又断言新行里含摘要「丙」，而追加分支根本不使用摘要参数（摘要在并入时才用）。
   三处断言逐层改对，并补一条「旧版本号只出现一次」——防的是**日志把版本记错**。

> 教训：用例写错和代码写错长得一样，都是红的。区别在于——**代码错是 bug，用例错是把 bug 写成规范**。
