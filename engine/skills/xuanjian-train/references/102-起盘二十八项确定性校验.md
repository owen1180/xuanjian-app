## 一、为什么是「校验器」而不是「排盘引擎」

源码把十四主星定位、五行局推算、命宫/身宫推导委托给 `iztro`，仓库本身只做
结果装配、亮度覆写与流派补丁（`algorithm.ts:6,489-500,622-623`）。
本馆不引入 `iztro`／`lunar-javascript` 依赖，也不搬实现；
把**能确定性验证的那部分**（结构、边界、铁律）做成发出前闸门，
这才是「算法深度理解」的可复用形式。

## 四、裁决：哪些对齐、哪些必须保留本馆口径

- **可对齐**：时辰索引、日期真实性、闰月四口径、四化白名单、十二宫结构、
  夏令时只判定、引证逐字可查。这些都是确定性事实，无流派分歧。
- **只是流派选择，不得当通用铁律**：源码「四化永远固定、大限只看宫位移动」、
  「宫干自化／来因宫／飞星派字段整体下线」是倪师南派三合派口径
  （`algorithm.ts:13-14,629-630,641`）。本馆按口径卡显式记录，不替别派定案。
- **直接冲突，保留本馆**：源码「13 维并列 + AI 自由追问」与本馆
  「各安其位、禁止越级抢答」冲突；「本人终点永不可断」本馆更严。
  《骨髓赋》「先看命宫→次看身宫→再看大限流年」可与紫微三步相互印证，
  **只作引证，不改三步顺序**。
- **宣传数字纠正**：源码实为 36 个具名格局／42 条 level、3 部古籍共 75 段、
  1848 条《天纪》原话；清单里的「24 组双星／37 种格局／6 部古籍 2532 段」源码无对应（`OB95` §二）。

## 五、用法

```bash
python3 paipan_check.py check - < card.json          # 28 项，FAIL 退出码 2
python3 paipan_check.py from-row '<v4.0 数据行 JSON>' # 数据行 → 最小盘面卡
python3 paipan_check.py --selftest                    # 17/17
```

`from-row` 让 `TR101` 的全量数据核验与起盘铁律直接连通：
任何一年一盘都可转成卡做确定性校验，无需引入排盘依赖。
