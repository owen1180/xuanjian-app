# TR111 · 自检的审计：别让「全绿」自证

> 2026-11-05｜第十七轮之后半｜v1.57.0
> 用户一句「继续提升自检」，问到了本馆最不该含糊的地方：**那些绿灯，是谁点的？**

---

## 1. 问题：全绿这句话，一直没有第三方

前十六轮，本馆说过很多次「N/N 全绿」。这句话有两个前提，从来没验过：

1. **自检本身不注水**——测的是真事，不是「函数不崩就行」。
2. **汇总本身不算错**——N 是多少，得是数出来的，不是记出来的。

第 2 条本轮当场应验：上一轮交账写「三层 21 个脚本 316/316」，
实测发现**只跑了 evolve／train／openbook 三层，kb 层七个自检脚本一个都没进汇总**（141 条）。
数字不是抄错，是**汇总口径漏了一层，而且没有任何机制会因此报错**。

第 1 条更隐蔽。注水有四种长相，全都显示通过：

| 型 | 长相 | 为什么没人发现 |
|---|---|---|
| 假自检 | `def 自检():` 里一条断言都没有，只 print「ok」 | 输出好看，退出码 0 |
| 恒真断言 | `assert True`／`assert 1 == 1`／`assert x == x` | 永远绿，等于没测 |
| 失败不落地 | 自检返回 1，但入口没传给 `sys.exit` | 失败了进程仍退 0 |
| 只测正不测负 | 脚本有 raise／拒绝分支，自检里没有一条「应被拒绝」的用例 | 「该拦的没拦」永远测不出来 |

## 2. 治法：自检元闸 `selftest_gate.py`

新建在 `xuanjian-openbook/scripts/`（与册号闸、册页自洽闸同类：**管质量，不管业务**）。

**技术选择：AST 静态读，不 import、不执行被测脚本。** 理由：一执行就有副作用（有的脚本会写文件、拉网、起子进程），
而本闸要能在任何环境下安全跑。代价是只能看见「写法」，看不见「语义」——所以它判的是**结构与纪律**，不是对错。

三条判据：

```
硬错误（strict 时 FAIL）：
  ① 自检函数存在但零断言          → 假自检
  ② assert True / assert x == x    → 恒真
  ③ 有自检却无 sys.exit 通路      → 失败不落地
欠账（只列不清算）：
  ④ 整脚本无自检 → 按行数排序点名，≥120 行标 ★
```

**无自检只算欠账、不算错**——有的脚本依赖资料库接口、外部工具、交互输入，确实测不了。
但欠账必须点名到「脚本＋行数」，因为**看不见的欠账会长成看不见的洞**。

三个命令：`盘点`（全表）／`欠账`（只列没测的）／`跑`（真跑一遍并汇总）。`--strict` 有注水即 FAIL。

### 2.1 两个必须认的写法（否则会误伤写得好的自检）

- **本地助手**：`def ck(名, 条件)` 这种自检内自定义助手，其调用同样是断言。
  不认它，`dataset_scan`（11 条）、`casebook`（23 条）都会被误判成「假自检」——**这是本闸第一版真实踩的坑**。
- **`cases.append((名字, 条件))`**：先收集再分拣的写法，每次 append 算一条断言。
  不认它，`build_corpus`（实跑 20 条）会显示成 1 条。

## 3. 补测的四件：为什么是它们

优先级不是按行数排的，是按「**它错了会不会静默放过错**」排的。

| 脚本 | 为什么最该补 | 补了什么（条数） |
|---|---|---|
| `kb/score.py` | 全馆旺衰判档的**唯一依据**（`judging_basis=score-py`）；它错＝四册九项全错，而错与对长得一样 | 47 条 |
| `evolve/regress.py` | 唯一的「改坏了没有」报警器；判错漂移级别要么静默放过、要么天天误报 | 18 条 |
| `evolve/ledger.py` | 「读过什么」的唯一账本；多算一份已读，就没人再去读那份资料 | 15 条 |
| `kb/yun.py` | 岁运引擎，且回归器的考点全靠它输出的**行首位置＋全角冒号**这条隐形契约 | 35 条 |

### 3.1 `score.py` 测的是四类不变量，不是「跑得通」

1. **值域**：天干增减必在 −50..30；克我必负、同我必正。
2. **边界不串档**：`判定(44.99)=太弱`／`判定(45)=偏弱`，六个阈值两侧各测一次，且六档顺序不乱、单调不减。
3. **恒等式**：`总分 = 天干分 + 地支分`、两次打分完全一致、过程里必须有「天干合计」这一行。
4. **表自洽**：藏干十二支齐备且**各支分值合计恰为 100**、本气必居首且最高、阴阳十干各半。

顺带查出一条**死分支**：`柱型()` 末尾的 `return "无关"` 永远不可达——五行两两非生即克，
干支关系必落五类之一。自检因此写成 `"无关" not in 全域`：**这句在守住「不许有人把它改成可达」**。

### 3.2 `yun.py` 测的是一条没人写下来的契约

`regress.py` 的 `要点()` 靠 `l.split("：")[0]` 从岁运行里抽「位置」，再拼成考点标签。
这条格式契约此前只存在于两个函数的默契里：**判岁运 换掉分隔符，回归器不会报错，只会安静地抽不到东西，然后一切照旧绿灯。**
现在写成断言：`判岁运` 每行必含全角冒号。

## 4. 自检本身也要能被改红（变异测试）

新写的自检，一律做一次「改坏它该抓的东西，看它红不红」。
`score.py` 实测三处：

| 变异 | 结果 |
|---|---|
| 把 `强弱档` 前两档对调 | 4 条红（判定·0 分落最弱档／44.99／45／六档顺序） |
| 把 `藏干["子"]` 从 100 改成 90 | 1 条红（各支分值合计为百分） |
| 把 `天干增减` 改成恒返回 0 | 12 条红（十条已知 + 符号两条） |
| 复原 | 47／47 全绿 |

**纪律：只加断言不验灵敏度，等于给门装了把假锁。** 本轮的 47／18／15／35 条都过了这一步。

## 5. 顺带查出的两件事（都没擅自改）

### 5.1 上一轮的 316 漏了一整层

`kb` 层七个自检脚本（huangli／meihua／qiming／xiaoliuren／zeri／kauding／score）共 141 条，
上一轮汇总时没进统计。**现在全包真数**：

| 层 | 脚本 | 断言 |
|---|---|---|
| evolve | 8 | 120 |
| kb | 7 | 141 |
| openbook | 5 | 79 |
| train | 10 | 181 |
| **合计** | **30** | **521（实跑全绿）** |

另有 6 个脚本只报「都对」不报条数（huangli／meihua／qiming／xiaoliuren／zeri／study），
按 AST 断言数计入并标「估」——**估的数要标出来，不许混进实数冒充**。

### 5.2 两处口径现状，记录不改

- **寅巳既相害又相刑，当前判「害」**（`关系()` 里 六害 先于 三刑 返回）。
  课程体例中「刑」通常重于「害」，但改它会改 `判岁运` 输出、连带回归基准漂移，
  **属未经定案的口径变更**，本轮只把它写成断言锁住现状，等定案。
- **`查空()` 输出行不带位置标签**（无全角冒号），`regress.要点()` 对它是退化的（整行当位置）。
  同样锁现状，改它要同步回归器与基准。

两处都写成「锁现状」的断言而不是「已知问题放行」：
**一旦有人改了，自检立刻变红，提醒去同步册页与回归基准**——这比写一句 TODO 有用。

### 5.3 元闸上线首日就抓到两处真注水

**`kauding.py` 三条恒真断言**：`ok("机梁同宫限定辰戌", {4, 10} == {4, 10})` 是纯占位，
另两条 `ok(…, True)` 写在 `except` 分支里——**一旦抛异常就「通过」，等于把「拒绝」写成了结论**。
处置：删掉占位那条（本工具不排星，机梁同宫属册页 `OB96`，要测也是在排盘工具的测试里）；
两条改写成「先置变量、except 里置真、最后断言一次」，14 条全真。

**`source_gate.py` 的 `checks` 列表写法被误判成假自检**：它把断言收进
`checks = [(名字, 条件, 备注), …]` 再统一跑，本闸第一版只认 `查()`／`ck()`／`append`，
于是把 11 条真断言看成 0 条。处置：检测器加第三种写法，
且要求元组**首元是字符串名字**——否则 `bad_dates = [(1925, 2, 29), …]` 这种数据表
会被当成 9 条断言，反倒误报 9 处恒真（这一版也踩过）。

**结论：审计工具要能被真样本校准，也要能被假样本校准。** 三条路的误报都出现过：
不认 `ck()` → 误报好自检；认前缀「判」 → 误报 `判定(44.99)`；认所有列表元组 → 误报日期表。

## 7. 硬约束与待办

**硬约束（不许破）**：

1. 报「全绿」必须同时报**跑了几个脚本、跑的是哪几层**——只报分子不报分母的口径，一律视为未报。
2. 只报结果不报条数的自检，汇总时必须标「估」，不许与实数混计。
3. 新脚本无自检可以被接受，但**必须能被 `欠账` 点到名**；不接受「大家都以为它在测」。
4. 恒真断言一律算错，不因历史遗留豁免。

**待办（按「静默放过错」的风险排序）**：

1. `kb_gate.py`（476 行，全馆内容闸）——最该补，逻辑分支最多。
2. `evolve.py`（294 行，进化日志与沉淀编排）——写错会把日志写歪，无人知。
3. `kb_audit.py`（245 行，册页自洽闸）——它是闸门的闸门。
4. `archive/kb_ledger.py`（292 行）／`ritual/query.py`（246 行）——依赖外部库，需先造桩。
5. `源 gate` 类（`source_gate.py`／`verify_quotes.py`）——引文核验，错在「放过了一条假引文」。

**本次未涉及**：定案级规则（四册九项、用忌神落地、紫微三步、`judging_basis=score-py`、
