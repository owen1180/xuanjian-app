## 一、为什么要回头对一手

册页是二手的：它是读课之后写下来的规矩。二手材料有个固定风险——**写得越顺，
越不像漏了东西**。`41` 册 §4.3 那张表把「得令取大、失令取小」写得很完整，
还配了一条月令口诀，读起来无懈可击；可它只写了「得令的月份长什么样」，
没写「每个五行到底哪几个月得令」的完整清单。

一手材料（课程笔记原页）里，这五条是逐一列出的。**清单型知识必须回一手核**，
因为二手的概括句天生会漏项，而且漏得看不出来。

## 二、查出的漏项：金在辰、未、丑

一手原话（《打分方法.pdf》「区间取值」节）：

| 取的本气 | 得令月份 |
|---|---|
| 火 | 春季、夏季 |
| 水 | 秋季、冬季 |
| 土 | 夏季，以及月支为土 |
| 金 | **秋季，以及月支为土** |
| 木 | 冬季、春季 |

`score.py` 的月令旺相表：辰 `{木火土}`、未 `{火土}`、丑 `{水木土}`——**三个月都漏了金**，
只有戌带了。

后果不是抽象的：金日主、带丙申／丁酉／甲申／乙酉这类「支金克干木火」的截脚柱、
生在辰未丑月，本气分会按**失令 0.7** 算而不是 0.8。每根这样的柱少 10 分，总分少 **4.5 分**：

```
丙申 壬辰 庚申 丁丑    改前 119.5（偏旺）  →  改后 124.0（偏旺）
丙申 壬子 庚申 丁丑    改前 119.5          →  改后 119.5（子月金本不得令，不动）
```

4.5 分在 115／105 那条线上足以改档——`41` 册 §4.5 自己写着「落在档界 ±5 分内必须复核」，
这条漏项正好落在这个带里。

## 三、两侧谁对：工具领先，脚本落后

专家包与排盘工具各有一份打分实现，同步闸一直让它们「逐条对齐」。
这次发现：工具侧 `src/analysis/scoring.ts` 的 `SEASON_MAX.金` 是
`申酉戌辰戌丑未`——**它本来就是对的**，错的只有专家包这一侧。

这条值得单独记，因为它违反直觉：

> 两侧不一致时，别默认「脚本是准的、工具是抄脚本的」。先问一句：**哪一边跟一手材料对？**

本轮之前的所有双侧修正都是「先改脚本、再同步工具」，于是形成了一种惯性：
把专家包当母本。这次反过来了——母本错了，抄本对了，而且抄本对得没道理地被放过
（因为「工具随脚本」这条规矩只看一致性，不看正确性）。

## 四、自检怎么写才算测得动

原来的断言是：

```python
查("月令旺相·当令者必在其中", all(支五行[z] in 月令旺相[z] for z in ZHI))
```

它只问「有没有当令的那一个」，对「少收了几个」毫无办法——**测「有没有」，测不出「够不够」**。

改成按一手材料那五条规则**反推**每月该有哪些五行，再与表逐支比对：

```python
得令支 = {"木": 冬+春, "火": 春+夏, "土": 夏+土月, "金": 秋+土月, "水": 秋+冬}
期望 = {z: {h for h, 支们 in 得令支.items() if z in 支们} for z in ZHI}
查("月令旺相·按五条规则反推逐支相符", 期望 == 月令旺相)
```

变异测试：把辰未丑的金去掉（还原旧表）→ 红 2 条；把戌的土去掉 → 红 2 条。
`score.py` 自检 47 → **51** 条。

**通用做法**：表型知识不要直接断言「表里有什么」，要用**生成规则**算出应有的表，
再整表比。前者只能测已知，后者能测未知。
